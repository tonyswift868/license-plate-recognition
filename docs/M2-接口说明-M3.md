# M2 车牌识别接口接入说明（M3）

面向刘一凡及 M3 后端。M2 是进程内 Python 包 `lpr`，不提供 HTTP 路由或数据库写入；M3 负责上传接收、抓拍图保存、业务建档/计费和人工确认。接口契约以《M2 车牌识别开发文档》第 5 章为准。本说明示例均以 FakeRecognizer 联调，不代表真实识别准确率。

## 安装与启动

在仓库根目录、M3 使用的 Python 3.11+ 环境中安装本地算法包：

```powershell
pip install -e ./algorithm
```

以上为接入说明中的安装命令，本批未实际执行 `pip install`。依赖由 `algorithm/requirements.txt` 声明。部署时将 `algorithm` 一起纳入后端环境，并确保模型与配置文件可读。生产/答辩识别器应在应用启动阶段创建一次；真实模式需要模型文件和匹配的 manifest。`PlateRecognizer.from_config()` 在配置或模型加载失败时抛 `ConfigError` / `ModelLoadError`，应让部署启动失败并修复配置或模型，不要等到首个请求才加载。

`.env` 约定键：

| 键 | 用途 | 实际读取方 |
| --- | --- | --- |
| `LPR_CONFIG` | 可选 TOML 配置文件路径；未显式传 `path` 时由 `PlateRecognizer.from_config()` 的配置加载器读取 | `lpr.config.load_config` |
| `LPR_FAKE` | M3 应用设置开关；`1` 时 M3 选择 `FakeRecognizer`，否则创建真实识别器 | M3 的 `.env`/Settings 加载代码；`lpr` 包本身不读取此键 |

示意：

```python
from lpr.testing import FakeRecognizer

recognizer = FakeRecognizer.from_config()  # 联调桩；生产代码由 M3 Settings 选择 real/fake。
recognizer.warmup()  # 应用启动时调用一次；FakeRecognizer 此操作为空
```

## 四个调用方法

`PlateRecognizer` 与 `FakeRecognizer` 方法签名一致。

| 方法 | 输入与用途 | 返回/约定 |
| --- | --- | --- |
| `recognize(image, *, lane_id=None, debug=False)` | 单张 OpenCV `numpy.ndarray`，BGR、`uint8`；适合已经解码的抓拍图。`lane_id` 用于选择车道 ROI；`debug=True` 会在对象的 `debug` 属性保留中间图 | `RecognitionResult`。HTTP/WS 响应请调用 `to_dict()`；不要直接 JSON 编码 ndarray |
| `recognize_bytes(data, *, lane_id=None)` | 单张 JPG/PNG 字节，适合 `UploadFile.read()` 的结果 | 同上；无法解码返回 `BAD_INPUT`，不会向请求处理器抛识别异常 |
| `recognize_many(images, *, lane_id=None)` | 同一辆车的多张图，元素可混合 JPG/PNG 字节与 BGR 数组；建议 1–5 张 | 真实 `PlateRecognizer` 会逐帧识别并投票；`frames_used` 表示投票使用帧数。空序列返回 `BAD_INPUT`。FakeRecognizer 是接口桩，只处理首帧并将 `frames_used` 设为输入项数，不模拟逐帧识别或投票 |
| `warmup()` | 无参数 | 启动阶段预热真实分类器，避免首个请求承担首次推理开销；FakeRecognizer 是空操作 |

初始化器 `PlateRecognizer.from_config(path=None, **overrides)` 加载配置和分类器。`path` 可指定 TOML 文件；省略时读取 `LPR_CONFIG`，再回退到 `algorithm/config/default.toml`。当前默认采用 plate_det_v1（检测输入 384）+ char_cnn_v2 / crnn_v4 / box_reader_v3 三路仲裁（011 + T20_A），框读模型随启动加载。历史配置留档：`algorithm/config/legacy_agree_v1.toml`（旧 agree 双路）、`algorithm/config/three_route_v2_det256.toml`（10-28 切换前的三路默认），对比/消融时显式传入。覆盖项采用双下划线，例如 `runtime__classifier="svm"`。切换分类器时还须配置匹配的 `runtime.model_path`，并确保模型同目录的 `manifest.json` 登记正确；只改分类器名称不会自动选择另一份模型。模型缺失、manifest/字符表校验失败或配置非法会分别抛 `ModelLoadError` / `ConfigError`。FakeRecognizer 也提供同名 `from_config()` 以便替换，但它不读配置且忽略覆盖值。

识别同步执行，异步 Web 框架应放到线程池，不能阻塞事件循环：

```python
import asyncio
from lpr.testing import FakeRecognizer

recognizer = FakeRecognizer()
recognizer.warmup()

async def recognize_upload_bytes(data: bytes, lane_id: int) -> dict:
    result = await asyncio.to_thread(
        recognizer.recognize_bytes, data, lane_id=lane_id
    )
    return result.to_dict()

print(asyncio.run(recognize_upload_bytes(b"not an image", lane_id=1))["status"])
```

## 同一车辆多图上传

按 Q10 的接口约定，入场与出场抓拍路由（`/api/v1/entry/capture`、`/api/v1/exit/capture`）应支持 multipart 多文件，建议一次传同一辆车的 1–5 张抓拍图。本说明描述预期接法：M3 路由读取全部文件字节后作为一个列表交给 `recognize_many`；不能把不同车辆的图片放进同一列表。M3 HTTP 路由是否已实现及端到端联调状态尚未在本批验证。保存原始抓拍图和文件路径仍由 M3 负责。

```python
import asyncio
from lpr.testing import FakeRecognizer

recognizer = FakeRecognizer()

async def recognize_uploads(frames: list[bytes], lane_id: int) -> dict:
    result = await asyncio.to_thread(
        recognizer.recognize_many, frames, lane_id=lane_id
    )
    return result.to_dict()

print(asyncio.run(recognize_uploads([b"not an image", b"bad"], lane_id=1))["frames_used"])
```

## `RecognitionResult.to_dict()` 字段

返回值只含 JSON 可序列化类型；`plate_image`、`debug` 等 ndarray 不在字典中。下表是当前实现的全部字段及转换规则。

| 字段 | 类型/空值 | 含义与序列化规则 |
| --- | --- | --- |
| `status` | string | 状态枚举值，如 `OK`、`NO_PLATE` |
| `error_code` | integer | `0` 或 3xxx 业务码 |
| `message` | string | 对应状态的中文说明 |
| `plate_no` | string 或 null | 最佳车牌猜测；失败状态通常为 null，低置信/格式错误可能有值 |
| `plate_color` | string | `blue`、`yellow`、`green`、`white`、`black` 或 `unknown` |
| `layout` | integer 或 null | 7 / 8 位版式；无结果时 null |
| `confidence` | number | 整牌置信度，四舍五入 4 位小数 |
| `char_confidences` | number[] | 各字符置信度，逐项四舍五入 4 位小数 |
| `candidates` | `[车牌, 分数][]` | 单帧结果按 `postprocess.topk` 返回候选，默认值为 3，可在配置中调整；每项 `[string, number]`，分数四舍五入 4 位小数。真实多帧投票当前只返回投票 Top-1，因此该场景通常只有一个候选 |
| `bbox` | integer[4] 或 null | 原图坐标 `[x, y, w, h]` |
| `corners` | number[2][] 或 null | 原图像素四角点，顺序 LT、RT、RB、LB，坐标 `[x, y]` |
| `elapsed_ms` | number | 总耗时毫秒，四舍五入 2 位小数 |
| `stage_ms` | object<string, number> | 阶段耗时毫秒，各值四舍五入 2 位小数；键按实际运行阶段出现 |
| `frames_used` | integer | 本次结果记录的帧数；单帧默认为 1 |
| `vehicle_type_hint` | string | `small`、`large` 或 `unknown`，仅供提示 |
| `model_version` | string | 识别器/模型版本；当前默认示例为 `lpr-1.0.0+char_cnn_v2+plate_det_v1+crnn_v4+box_reader_v3`；FakeRecognizer 为 `lpr-fake` |

状态码和业务含义以 `status` 为准；M3 不要自行复算阈值，也不要把模型置信度当作放行决定。

## 状态、3xxx 码与 M3 处置

| status | error_code | 结果特点 | 建议处置 |
| --- | ---: | --- | --- |
| `OK` | 0 | 达到当前识别阈值 | 正常进入业务流程；仍按业务规则建档/计费 |
| `NO_PLATE` | 3001 | 未找到车牌，`plate_no=null` | 提示人工录入或重新抓拍 |
| `LOW_CONFIDENCE` | 3002 | 有最佳猜测，`plate_no` 通常有值 | 岗亭提示人工确认；可展示 `candidates` 供改牌 |
| `SEG_FAILED` | 3003 | 已定位但字符切分失败，通常无车牌号 | 提示人工录入或重新抓拍 |
| `INVALID_FORMAT` | 3004 | 有字符串结果但不符合版式 | 人工确认，不自动放行 |
| `BAD_INPUT` | 3005 | 空图、坏编码、类型错误或图像太小 | 提示重新抓拍/检查上传编码；不要当作无车牌 |
| `UNSUPPORTED` | 3006 | 当前不支持的特种车牌，例如白牌/黑牌 | 提示“特种车牌暂不支持”，转人工录入 |
| `INTERNAL_ERROR` | 3099 | 算法内部异常，细节在算法日志 | 不阻塞主流程，转人工；记录请求关联信息并告警排查 |

除 `from_config()` 外，四个识别/预热方法按契约不把单次识别错误抛给调用方；调用后检查 `result.status` 与 `error_code`。不要只判断 `plate_no is None`，因为 `LOW_CONFIDENCE` 和 `INVALID_FORMAT` 也可能返回猜测值。

## FakeRecognizer 联调方式

FakeRecognizer 不加载模型、不运行真实图像算法，只验证接口串接、响应序列化和 UI 分支。以下三种方式可独立使用或组合：

1. **默认轮换成功结果**：`FakeRecognizer()` 按预设车牌列表轮流返回 `OK`，适合冒烟检查。
2. **按序列模拟状态**：`FakeRecognizer(script=["OK", "LOW_CONFIDENCE", "NO_PLATE"])`，请求依次返回这些状态并循环；可用 `RecogStatus` 枚举替代字符串。
3. **按演示文件名返回状态**：把演示图放进目录并构造 `FakeRecognizer(samples_dir=演示图目录)`。文件内容需与上传内容相同，状态由文件名主干决定：

| 演示文件名 | 结果 |
| --- | --- |
| `陕A12345.jpg` | `OK`，返回 `陕A12345` |
| `陕A12345__LOW.jpg` | `LOW_CONFIDENCE`，仍返回该车牌供人工确认 |
| `陕A12345__INVALID.jpg` | `INVALID_FORMAT` |
| `NO_PLATE_1.jpg` | `NO_PLATE`；同规则可用 `SEG_FAILED_1.jpg`、`UNSUPPORTED_1.jpg`、`BAD_INPUT_1.jpg`、`INTERNAL_ERROR_1.jpg` |

字节无法解码或空/非法数组仍返回 `BAD_INPUT`。不匹配 `samples_dir` 中内容时回到默认或 script 行为。FakeRecognizer 的 `recognize_many` 只根据首帧决定状态/车牌，再把输入项数量写入 `frames_used`；它不验证多帧一致性、逐帧失败处理或投票结果。答辩识别演示应使用真实 `PlateRecognizer`，FakeRecognizer 不能用于性能、准确率或多帧投票结论。

## 线程安全与运行约定

- `PlateRecognizer` 初始化一次并在应用进程内复用；识别实例可被多个线程并发调用。每个请求把阻塞识别放入 `asyncio.to_thread` 或框架线程池。
- `warmup()` 在启动阶段调用一次。真实识别器会设置 PyTorch CPU 线程数（默认配置为 2）；避免每个请求重复创建模型或执行预热。
- `FakeRecognizer` 的轮换车牌和 script 游标受内部锁保护；并发请求下返回顺序可能由调度决定，不应依赖某请求对应固定序号。要按文件验证固定状态，使用 `samples_dir`。
- `PlateVoteSession` 与 `DuplicateFilter` 属于有状态组件，按车道分别创建和维护；不要把它们和识别器实例的无状态并发约定混为一谈。
- M3 读取 `.env` 并构建自己的 Settings；其中 `LPR_FAKE` 由 M3 选择 fake/real，`LPR_CONFIG` 可由 `lpr` 配置加载器直接读取。环境变量应在应用启动前设置。

## 可运行联调示例

下面代码覆盖单图 ndarray、字节输入、坏输入、顺序脚本、文件名映射、多帧和 asyncio 调用。将 `DEMO_DIR` 指向已创建的演示图目录；目录示例通过 OpenCV 生成纯色测试图片，文件名模拟上述规则。FakeRecognizer 按图片内容哈希匹配这些文件。

```python
import asyncio
import cv2
import numpy as np
from pathlib import Path
from lpr.testing import FakeRecognizer

demo = Path("algorithm/out/receipts/第三批-m3/demo")
demo.mkdir(parents=True, exist_ok=True)
ok_img = np.full((120, 240, 3), 80, np.uint8)
low_img = np.full((120, 240, 3), 100, np.uint8)
np_img = np.full((120, 240, 3), 120, np.uint8)
for name, image in [("陕A12345.jpg", ok_img),
                    ("陕A12345__LOW.jpg", low_img),
                    ("NO_PLATE_1.jpg", np_img)]:
    ok, encoded = cv2.imencode(".jpg", image)
    assert ok
    (demo / name).write_bytes(encoded.tobytes())

async def main():
    # 1. 默认轮换 + ndarray API
    default = FakeRecognizer()
    default.warmup()
    r = default.recognize(ok_img, lane_id=1)
    print("default", r.status.value, r.plate_no, r.to_dict()["model_version"])

    # 2. script 状态轮换 + JPG bytes API + 空多帧输入
    scripted = FakeRecognizer(script=["OK", "LOW_CONFIDENCE", "NO_PLATE"])
    encoded_ok = cv2.imencode(".jpg", ok_img)[1].tobytes()
    for _ in range(3):
        r = scripted.recognize_bytes(encoded_ok)
        print("script", r.status.value, r.error_code)
    bad = scripted.recognize_bytes(b"not an image")
    print("bad", bad.status.value, bad.error_code)

    # 3. 按演示文件名映射；内容需与目录里的文件一致
    mapped = FakeRecognizer(samples_dir=demo)
    for name in ("陕A12345.jpg", "陕A12345__LOW.jpg", "NO_PLATE_1.jpg"):
        r = await asyncio.to_thread(mapped.recognize_bytes,
                                    (demo / name).read_bytes(), lane_id=2)
        print("file", name, r.status.value, r.error_code, r.plate_no)

    # 同一车辆的两张图作为一组；输出 frames_used=2
    r = await asyncio.to_thread(mapped.recognize_many,
                                [(demo / "陕A12345.jpg").read_bytes(),
                                 (demo / "陕A12345__LOW.jpg").read_bytes()],
                                lane_id=2)
    print("many", r.status.value, r.frames_used)

asyncio.run(main())
```
