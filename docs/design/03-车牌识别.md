## 3.1 模块职责与边界

M2 识别部分提供进程内 Python 包 `lpr`，承接 R1、FR-01、FR-02：从入场、出场抓拍图中提取车牌信息，返回可供业务层判断的状态、置信度和图像证据。六阶段采用 OpenCV、NumPy、PyTorch 和 scikit-learn，自主训练字符分类器，不调用车牌识别服务，不使用现成识别模型或预训练车牌权重。运行与训练均面向 Windows 10/11、Python 3.12、CPU 环境；OpenCV 项目依赖约束为 `>=4.9,<5`。

| 需求／协作项 | 本模块职责 | 其他模块职责 |
| --- | --- | --- |
| R1、FR-01、FR-02 | 预处理、定位、校正、分割、识别、后处理 | 采集层提供上传图片或视频帧；本章不实现抽帧设备与车辆检测器 |
| E1 | 返回失败状态、低置信标记、最佳猜测和备选车牌 | M3/M6 完成人工录入与改牌，保留原抓拍图 |
| E7 | 提供重复抓拍判定，不自行丢弃业务事件 | M3/M5 保证停车会话和数据库事务幂等 |
| G1、G2、G3、G7 | 提供识别评测、吞吐评测和核心包测试方法 | M8 组织系统级测试、视频回放与交付验收 |
| 对外调用 | `PlateRecognizer`、`PlateVoteSession`、`DuplicateFilter` | M3 实现既有 `/api/v1/entry/capture`、`/api/v1/exit/capture` 和车道事件流程 |
| 持久化与放行 | 返回识别字段和车型提示 | 抓拍图落盘、`image_path`、停车会话建档、计费、费率、缴费与放行均由业务及数据层处理 |

本模块不新增 HTTP 路由，不修改接口路径和数据库表名。阶段一的图像增强属于识别算法；采集层的设备管理与视频抽帧属于独立边界。车型提示仅供业务侧参考，不能代替车辆档案及放行规则。

## 3.2 对外接口与数据契约

### 3.2.1 PlateRecognizer 调用接口

| 编号 | 接口 | 输入及输出 | 约定 |
| --- | --- | --- | --- |
| M2-PY-01 | `PlateRecognizer.from_config(path=None, **overrides)` | 可选 TOML 路径及覆盖项 → 识别器 | 默认配置打底，再选显式 path 或 `LPR_CONFIG`，最后合并 overrides；初始化可抛 `ConfigError`、`ModelLoadError` |
| M2-PY-02 | `warmup()` | 无业务输入 → `None` | 预热 8 字符分类批次及空白帧流水线；预热分类失败记警告 |
| M2-PY-03 | `recognize(image, *, lane_id=None, debug=False)` | 单张图像 → `RecognitionResult` | 推荐 BGR `uint8`；也接受二维灰度或单通道 `uint8`，内部转 BGR；按车道应用 ROI |
| M2-PY-04 | `recognize_bytes(data, *, lane_id=None)` | jpg/png 字节 → `RecognitionResult` | 解码失败返回 `BAD_INPUT`；结果耗时包含解码，`stage_ms` 增加 `decode` |
| M2-PY-05 | `recognize_many(images, *, lane_id=None)` | 同一车辆的图像数组或字节序列 → 投票结果 | 内部逐帧识别后投票；空序列返回 `BAD_INPUT`；一次 1—5 帧为接入建议，代码没有强制该数量上限 |
| M2-PY-06 | `version` | 只读属性 → 字符串 | 形式为 `lpr-包版本+分类器版本`，随结果返回 |

`recognize*` 捕获运行期算法异常，返回状态与错误码，不向正常调用方传播算法异常。配置与模型加载错误在初始化阶段暴露，避免服务启动后才发现模型不可用。M3 应在启动时构造识别器并预热；异步后端通过 `asyncio.to_thread` 或线程池调用同步识别方法，避免阻塞事件循环。

`runtime.torch_threads=2` 在 `from_config` 中设置；识别器不在调用之间维护可变识别状态，CNN 使用 eval 和 `torch.inference_mode()`。有状态的投票与去重对象另行加锁，按车道组织。联调可使用 `FakeRecognizer` 或均匀概率分类器，但其结果不能用于 R1 演示或性能、准确率验收。

### 3.2.2 RecognitionResult

| 字段 | 类型／含义 | 空值与单位 |
| --- | --- | --- |
| `status`、`error_code`、`message` | 枚举状态、0或3xxx码、提示文字 | 状态是业务侧分支处理依据 |
| `plate_no` | 车牌字符串 | 无有效识别内容时为 `None`；低置信或格式异常可保留猜测 |
| `plate_color` | blue/yellow/green/white/black/unknown | 无结果时为 unknown |
| `layout` | 字符数量 7/8 | 无结果时为 `None`；L7/L8S/L8L 名称属于解码中间结果 |
| `vehicle_type_hint` | small/large/unknown | 车型提示；默认 unknown |
| `confidence` | 整牌置信度 | 单帧为选中字符原始分类概率的最小值；范围0—1 |
| `char_confidences` | 逐位原始分类概率列表 | 不在允许字符子集内重新归一化；多帧时改用投票平均权重 |
| `candidates` | `(车牌, 分数)` 列表 | 默认 Top-3，由 `postprocess.topk` 控制；单帧候选分数是 beam 内归一化选择分，不能当作整牌置信度 |
| `bbox` | `(x,y,w,h)` | 原图像素；无结果时为 `None` |
| `corners` | 四角点 LT、RT、RB、LB | 原图像素 `(x,y)`；无结果时为 `None` |
| `plate_image` | 校正后的 BGR `uint8` 图 | 常规7位252×80、8位276×80；无结果时为 `None` |
| `elapsed_ms` | 调用总墙钟时间 | 毫秒；多帧含逐帧处理与投票 |
| `stage_ms` | 各阶段累计耗时字典 | 毫秒；候选与版式回退重复执行时累加 |
| `frames_used` | 实际参与投票的有效同长度帧数 | 单帧默认1；多帧回退为1或0，未必等于输入帧数 |
| `model_version` | 算法包与分类器版本 | 便于追溯 |
| `debug` | 中间 ndarray 字典 | 默认 `None`；仅单帧 `debug=True` 时返回工作图、校正图和字符拼接图等 |

`to_dict()` 排除 `plate_image` 和 `debug`，将其余字段转换为 JSON 兼容类型；置信度保留4位小数，耗时保留2位小数。图像落盘或单独编码由调用侧处理，不向 JSON 直接塞入 ndarray。通用失败结果将几何、车牌及校正图置空，置信度为0。

### 3.2.3 状态与错误码

| 状态 | 码 | 触发条件 | M3/M6 处理 |
| --- | --- | --- | --- |
| `OK` | 0 | 版式合法，整牌置信度达到阈值 | 继续业务校验，不直接等同允许放行 |
| `NO_PLATE` | 3001 | 定位无候选 | 人工录入 |
| `LOW_CONFIDENCE` | 3002 | 有合法格式猜测，但置信度不足 | 预填猜测并人工确认 |
| `SEG_FAILED` | 3003 | 有候选，所有尝试均未得到可用分割和解码 | 人工录入 |
| `INVALID_FORMAT` | 3004 | 最佳解码结果不符合版式正则 | 人工确认或改牌 |
| `BAD_INPUT` | 3005 | 图像类型、形状、尺寸或解码无效 | 重新抓拍 |
| `UNSUPPORTED` | 3006 | 未得到提前返回的OK，且首候选校正后颜色为白或黑 | 提示特种车牌暂不支持，转人工 |
| `INTERNAL_ERROR` | 3099 | 未预期算法异常或非法阶段输出 | 记日志，转人工，保持业务主流程可用 |

映射以 `errors.py` 为准；后续接口文档若调整细分码，应经架构师同步，不改变状态语义。不能仅按 `plate_no` 是否非空判断自动通过。当前代码先返回首个 `OK`，再在耗尽尝试后检查白/黑首候选，因此白/黑色并非校正后无条件提前拒绝；这是实现边界，不应写成已经具备完整特种牌分类能力。

## 3.3 六阶段总体流程

![图 5 车牌识别六阶段流水线](docs/img/pipeline.png)
（draw.io 源文件：docs/img/src/pipeline.drawio）

图5由图稿任务单独交付，本章保留规定引用。下面的宽×高描述用于图像，数组形状按高×宽×通道描述。原图与工作图坐标必须分清，NumPy 索引用 `[y,x]`。

| 阶段 | 输入 | 输出 |
| --- | --- | --- |
| 1 预处理 | 原图 `H0×W0×3 uint8`，也接受二维灰度或`H0×W0×1 uint8`；可选 ROI | `PreprocessOut`：工作BGR、同尺寸灰度及HSV、scale、offset |
| 2 定位 | 工作图及增强灰度、HSV | 至多3个 `PlateCandidate`，几何均为原图坐标 |
| 3 校正 | 原图及一个候选 | `RectifiedPlate`：BGR校正图、layout、颜色、原图到校正图的单应矩阵 |
| 4 分割 | 校正图及待尝试长度7/8 | `SegmentResult`：ok、layout、校正图坐标字符框、`N×32×32 uint8`、quality |
| 5 识别 | `N×32×32 uint8` | `N×65 float32` 概率，每行和为1 |
| 6 后处理 | 概率、长度、颜色 | `DecodeResult`：车牌、版式、逐位概率、置信度、候选、状态和车型提示 |

流水线伪代码如下；它只描述编排，不是可直接执行的实现源码。

```text
校验输入；预处理失败则返回 BAD_INPUT
pre = preprocess(image, cfg.preprocess, 车道ROI)
candidates = locate(pre, cfg.locate, runtime.max_candidates)
若 candidates 为空：返回 NO_PLATE
best = 空；lead_color = 首候选颜色
依得分顺序遍历至多3个候选：
    rect = rectify(原图, candidate, cfg.rectify)
    若为首候选：lead_color = rect.color
    已知长度先尝试该长度；未知长度尝试 [7,8]
    对 yellow/unknown 追加另一长度（不重复）
    对每个待尝试长度：
        seg = segment(rect, length, cfg.segment)
        若分割失败：继续
        dec = decode(classifier.predict_proba(seg.chars), length, rect.color, cfg.postprocess)
        按状态等级、再按confidence更新best
        若dec为OK：立即返回best的RecognitionResult
若lead_color为white/black：返回UNSUPPORTED
若best存在：返回best；否则返回SEG_FAILED
```

状态排序为 `OK > LOW_CONFIDENCE > INVALID_FORMAT`，同等级取较大置信度；但首个 `OK` 已提前结束，不会继续寻找更高置信度的其他候选。阶段未预期异常由外围捕获为 `INTERNAL_ERROR`，不会被当作普通分割失败静默忽略。

## 3.4 阶段一：预处理

**输入／输出：** 原图与 `PreprocessConfig`、可选原图ROI → `PreprocessOut`。工作宽度为上限，窄图不放大，高度按比例计算。缩放关系为 `工作坐标=(原图坐标-offset)×scale`。

**处理步骤：** 校验非空、uint8、灰度或1/3通道及最短边；ROI 与原图求交并再次校验尺寸；仅等比例缩小；从工作BGR生成灰度，执行CLAHE和高斯滤波；HSV从未增强的工作BGR生成。

```text
检查输入类型、尺寸和预处理参数
灰度或单通道 → BGR
若有ROI：求与原图交集，裁剪，保存实际左上角offset
scale = min(1, work_width / 裁剪后宽度)
work_bgr = 等比例缩小或复制
gray = BGR转灰度 → CLAHE → GaussianBlur
hsv = work_bgr转HSV
返回(work_bgr, gray, hsv, scale, offset)
```

| 参数 | 当前值 | 来源与限制 |
| --- | --- | --- |
| `preprocess.min_side` | 120 px | 原图与ROI裁剪图最短边均需达到 |
| `preprocess.work_width` | 800 px【待调】 | 只缩小，不放大 |
| `preprocess.clahe_clip` | 2.0 | CLAHE对比度限制 |
| `preprocess.clahe_grid` | 8 | 网格8×8，须为正数 |
| `preprocess.blur_ksize` | 5 | 5×5高斯核，须为正奇数 |
| `[lanes]` | 默认空 | 无车道ROI时使用全图；ROI为整数 `(x,y,w,h)` |

**失败情形：** 空图、错误类型或通道、最短边不足、ROI无交集或裁剪后太小、ROI/参数非法，抛阶段输入异常，由流水线返回 `BAD_INPUT`。其他意外异常由统一兜底处理。输入图不被就地修改。

## 3.5 阶段二：车牌定位

**输入／输出：** `PreprocessOut` → 按分数排序的原图坐标候选。候选四点按LT、RT、RB、LB排列，`source`为color、edge或merged。

**处理步骤：** HSV蓝/黄/绿掩膜经5×5中值滤波；增强灰度做Sobel-x、绝对值转换及Otsu二值化。各分支闭运算连接水平结构，再3×3开运算去噪。轮廓的最小外接旋转矩形经几何过滤后，临时校正到136×36计算颜色比例和中间18行的水平二值跳变数。综合评分后反算原图坐标并做NMS；跨分支重叠证据合并，适用时保留同色、更大颜色框，再次抑制重叠。

```text
masks = 蓝/黄/绿HSV掩膜中值滤波 + Sobel-x(gray)的Otsu结果
对各mask做闭运算、开运算
对各轮廓：
    r = 最小外接旋转矩形；过滤宽高比、面积比、倾角
    将r暂时校正到136×36，计算颜色占比与行跳变
    score = .35×比例接近度 + .35×颜色占比 + .30×跳变得分
    corners_original = corners_work / scale + offset
    裁到ROI对应原图范围，生成bbox与候选
按score降序NMS；合并跨分支证据后再抑制
返回前max_candidates个候选
```

| 参数 | 当前值 | 性质 |
| --- | --- | --- |
| `locate.aspect_min / aspect_max` | 2.0 / 5.5 | 几何过滤 |
| `locate.area_ratio_min / area_ratio_max` | 0.001【待调】 / 0.08 | 旋转矩形面积／工作图面积 |
| `locate.max_tilt_deg` | 30° | 上边倾角上限 |
| `locate.close_kernel_rel` | `[0.022,0.006]`【待调】 | 核宽、高均乘实际工作图宽度后取整，最少1 |
| `locate.min_row_transitions` | 12 | 跳变评分达到满分的参考值，不是独立硬拒绝条件 |
| `locate.nms_iou` | 0.3 | IoU严格大于阈值视为重叠 |
| `locate.blue_hsv` | `[100,70,40]`—`[124,255,255]`【待调】 | OpenCV H范围0—179 |
| `locate.yellow_hsv` | `[15,90,70]`—`[35,255,255]` | 以当前配置为准 |
| `locate.green_hsv` | `[35,50,60]`—`[90,255,255]` | 以当前配置为准 |
| `runtime.max_candidates` | 3 | 排序后最多保留数量 |
| 评分参考比例、颜色门槛 | 3.14／3.43；0.15 | 代码常量；有色占比不足则unknown |
| 分支滤波、评分图尺寸 | 中值5×5、开核3×3、136×36 | 代码常量；闭核由配置生成 |

**失败情形：** 中间图/scale无效或无合格轮廓时返回空候选，流水线返回 `NO_PLATE`。同色车身、反光、夜间偏色、面积过小会降低定位可靠性，边缘分支、车道ROI与候选回退用于补救。当前未接入独立车牌/非车牌二分类器，不能把设计中的可选复核写成已执行步骤。

## 3.6 阶段三：透视校正与判色

**输入／输出：** 原始图像、单个 `PlateCandidate`、`RectifyConfig` → `RectifiedPlate`。几何变换始终从原图取样；单应矩阵表示原图到最终校正图的映射。

**处理步骤：** 扩大候选框并与原图求交；先颜色、后边缘分支查找匹配轮廓，按面积、边界接触和IoU筛选，再由凸包多边形逼近获得四角点。没有合格四边形时退回候选点的最小外接矩形。先校正到252×80判色：绿牌改用276×80和8位；蓝黄牌初始为7位；白黑及未知为layout=0。

```text
校验原图和候选；灰度转BGR
quad = 原图扩边区域的颜色/边缘轮廓精修
若精修失败：quad = 候选点的最小外接矩形四点
M = quad(LT,RT,RB,LB)到[(0,0),(251,0),(251,79),(0,79)]的变换
plate = warpPerspective(原图,M,252×80)
color = 校正图内区颜色分类
若green：layout=8，按276×80重新求M和plate
否则若blue/yellow：layout=7；否则layout=0
返回plate、layout、color、M、candidate
```

| 参数 | 当前值 | 性质 |
| --- | --- | --- |
| `rectify.size_7 / size_8` | `[252,80] / [276,80]` | 配置尺寸冻结 |
| `rectify.expand_ratio` | 0.10 | 候选框各侧扩展比例 |
| `rectify.deskew_max_deg` | 10° | 保留配置字段，当前默认校正未读取；不代表已执行旋转搜索 |
| 轮廓筛选 | 面积为候选的0.40—1.8倍；框IoU≥0.45 | 代码常量；触碰扩边裁剪边界的轮廓不采用 |
| 四边形精修 | 逼近系数0.01/0.02/0.035/0.05 | 代码常量；要求凸四边形、最短边>2、边长比例1.8—6 |
| 边缘精修 | Canny 50/150 | 代码常量；颜色分支优先 |
| 判色内区 | 去掉上下各10%、左右各5% | 代码常量 |
| 蓝/黄/绿判色 | HSV范围同当前定位初值；比例≥0.15 | `rectify.py`独立常量；不会随locate配置覆盖自动变化 |
| 白/黑判色 | 白：S<35且V>175占比>0.6；黑：V<35占比>0.6 | 有色判定之后的代码规则 |

**可选能力：** 独立函数 `deskew_vertical(rect,max_shear=0.3,step=0.01)` 搜索残余垂直错切，max_shear允许0—0.3、step允许0.005—0.1，中心区为宽6%—94%、高12%—88%，以竖直投影谷和斜率先验评分；改善不足0.015或斜率绝对值不足0.05时不改变图像。它由外部显式调用，未接入 `PlateRecognizer` 默认流程，也没有新增统一配置开关；如使用，返回矩阵更新为错切矩阵乘原矩阵。不能将其写成默认旋转纠偏步骤。

黄色或未知颜色在编排中追加另一长度时，不会再次按该长度重做校正；分割在现有校正图上按相对槽位尝试。不能把“尝试8位”一概解释为该候选已重新采样到276×80。

**失败情形：** 图像、四点、面积或框无效，或候选与原图无交集时阶段抛错；流水线统一转 `INTERNAL_ERROR`，不会在此直接返回 `BAD_INPUT`。精修轮廓不足采用几何回退；若回退图截断字符，后续分割可能失败并尝试其他版式或候选。

## 3.7 阶段四：字符分割

**输入／输出：** 校正车牌及明确待试长度7/8 → `SegmentResult`。成功输出N个字符框、`N×32×32 uint8`字符图及质量值；失败为ok=False、空框、`0×32×32`及quality=0。

**处理步骤：** 灰度极性统一为亮字暗底；二值化；先记录边界连通域，再由行跳变裁掉字符带之外的区域，移除边界组件和小组件；基于配置的槽位中心与宽度搜索平移、缩放，使槽位墨迹覆盖最大且截断较少；槽内收紧墨迹框并验证几何，最后对灰度裁剪调用共享归一化。

```text
若长度/槽配置无效：返回失败
gray = unify_polarity(校正图灰度, color)
binary = Otsu或adaptive(gray)
记录边界连通域；依据行跳变确定字符带
删除带外像素、边界组件与小组件
搜索槽位缩放和平移；相邻槽用中点限制重叠
对每槽：收紧墨迹框，检查墨迹量、宽高、顺序和边缘截断
    chars追加normalize_char(gray[框])
检查整体覆盖率及高度一致性
quality = clip(coverage×(1-字符高度标准差/平均高度),0,1)
返回成功结果
```

| 参数 | 当前值 | 性质 |
| --- | --- | --- |
| `segment.binarize` | otsu | 配置可选adaptive；后者代码使用高斯窗口15、C=-5 |
| `segment.layout7_centers` | `[0.086,0.216,0.395,0.525,0.655,0.784,0.914]` | 相对板宽【待核实】【待校准】 |
| `segment.layout7_char_w` | 0.102 | 相对板宽【待校准】 |
| `segment.layout8_centers` | `[0.079167,0.187500,0.379167,0.487500,0.595833,0.704167,0.812500,0.920833]` | 配置已有临时值【待 CCPD2020 校准】 |
| `segment.layout8_char_w` | 0.09375 | 临时值【待 CCPD2020 校准】 |
| `segment.char_size` | 32 | 冻结输出尺寸 |
| 行带／小组件 | 行跳变≥6、高度8%—92%；面积<0.002WH删除 | 代码常量；跨边界或大框组件同时清除 |
| 槽位对齐 | 缩放0.90—1.08共10档，水平偏移±0.06W、步长2px | 搜索半径为`W×char_w×scale×0.65`；不是直接固定宽度裁切 |
| 字符框门槛 | 宽0.015W—0.15W，高0.32H—0.90H；单槽墨迹≥0.002WH | 代码常量 |
| 整体质量门槛 | coverage≥0.85；最矮高度≥最高的0.65 | 代码常量；槽边墨迹>字符高0.40则失败 |

槽位先验能将省份字的多个断开笔画归入同一字符框，避免仅按连通域个数切分。当前代码通过行带和连通域清除边框噪声，没有独立铆钉检测器，也未另行实现槽内投影谷切字。槽位评分包含总墨迹、最弱槽墨迹、边界墨迹惩罚及平移/缩放先验。

**失败情形：** 空槽、墨迹不足、字符宽高异常、框重叠、明显截断、覆盖不足、高度不一致，以及受控的图像/数值异常，均返回分割失败供编排回退。`quality`用于诊断，不是整牌概率；当前编排不把它再乘入分类置信度。

## 3.8 阶段五：字符识别

**输入／输出：** 亮字暗底的`N×32×32 uint8` → 冻结字符表顺序的`N×65 float32`，每行和为1。空批次返回`0×65`。字符表为31省份、10数字、24字母，不含字母I、O；训练标签与模型输出下标严格一致，`CHARSET_SHA=ea8a61c65117`。

**处理步骤：** 检查批次规格并处理空批次，按初始化时选择的模型执行特征计算与预测，再按冻结类别顺序返回概率。分割阶段已完成归一化，识别封装不再次改变字符几何；CNN另做浮点转换和像素除255，模板及SVM使用各自的概率映射。

```text
校验字符批次形状和uint8类型
若N=0：返回空概率矩阵
按runtime.classifier选择已加载模型：
    cnn：转N×1×32×32 float32并除255，在eval/inference_mode中softmax
    template：与65类均值模板做归一化相关，温度softmax
    svm：OpenCV HOG得到324维，概率SVC或校准器predict_proba
返回按CHARSET排列的float32概率
```

| 参数／规范 | 当前值 | 来源 |
| --- | --- | --- |
| `runtime.classifier` | cnn | 配置另支持template、svm |
| `runtime.model_path` | `models/char_cnn_v1.pt` | 配置相对路径以algorithm目录解析；换分类器必须匹配模型路径 |
| 共享归一化 | 长边缩至28、保持比例、线性拉伸0—255、居中贴32黑底 | `charnorm.py`；黄/绿/白反色，蓝/黑保持极性 |
| CNN输入与模式 | 像素/255，CPU、eval、inference_mode | 推理代码；线程数由初始化配置控制 |
| 模板温度 | 0.1【待校准】 | 模板生成工具默认值，随npz保存 |
| SVM特征 | HOG窗口32×32、块16×16、步8×8、胞8×8、9方向，324维 | OpenCV HOGDescriptor；不使用scikit-image |

**失败情形：** 输入形状/类型非法、模型运行失败或OpenCV构建缺少HOG时抛错，由编排转为 `INTERNAL_ERROR`。模型缺失、未登记、字符表哈希或已有文件哈希不一致，或权重不兼容，在 `from_config` 阶段以 `ModelLoadError` 失败。不得将分类器输出的高概率解释为整牌必然正确，最终仍需位置约束和人工复核阈值。

## 3.9 阶段六：版式约束与后处理

**输入／输出：** `N×65`概率、所试长度、颜色与配置 → `DecodeResult`。模型概率保持原值，只复制一份选择权重供省份先验和beam排序使用。

**处理步骤：** 校验概率矩阵，构造各版式的位置允许集合；使用选择权重选字符，按原始概率比较版式；计算最小逐位置信度、正则和阈值状态；生成beam候选及车型提示。选择分、候选分与对外置信度分别保留含义，不相互替代。

| 版式 | 位置允许集合 | 全串校验含义 |
| --- | --- | --- |
| L7 | PROV、LETTER、ALNUM×5 | 省份字＋无I/O字母＋5位字母数字 |
| L8S | PROV、LETTER、DF、ALNUM、DIGIT×4 | 小型新能源形式 |
| L8L | PROV、LETTER、DIGIT×5、DF | 大型新能源形式 |

PROV为31省份；LETTER为24字母；ALNUM为34字母数字；DIGIT为10数字；DF为D或F。正则在 `plate_rules.py` 使用fullmatch，首位集合由冻结省份表构造，不把“省份”二字当作字面字符集合。

```text
校验probs形状=(layout,65)、有限、范围[0,1]、每行和约为1
weights = probs副本；仅首位按province_prior乘选择系数
对该长度的每种版式假设：
    各位置在允许集合内取weights最大字符
    记录该字符在probs中的原始概率p_i
    假设得分 = Σlog(p_i)
选择假设得分最高者；plate为逐位字符拼接
confidence = min(p_i)
若不满足全串正则：INVALID_FORMAT
否则confidence >= min_confidence：OK；否则LOW_CONFIDENCE
按允许槽集合做topk beam搜索，并在返回beam内归一化选择分
返回状态、车牌、版式名、原始置信度、候选及车型提示
```

| 参数 | 当前值 | 含义 |
| --- | --- | --- |
| `postprocess.min_confidence` | 0.80【待调】 | 单帧和投票状态判定的默认阈值；仅M2维护此阈值 |
| `postprocess.topk` | 3 | 默认备选数量；beam分数不等同整牌置信度 |
| `postprocess.province_prior` | `{}` | 默认关闭；系数须有限且>0，只影响选择权重，不提高对外原始概率 |

车型提示：蓝色L7为small、黄色L7为large；有受支持颜色的L8S为small、L8L为large；白/黑/未知为unknown。不能只凭8位就固定为small。

**失败情形：** 矩阵形状、概率、行和、topk、阈值或先验非法，解码抛 `ValueError`，编排转 `INTERNAL_ERROR`；合法矩阵生成的格式异常保留为 `INVALID_FORMAT`。不支持的汉字末位、特殊牌等不保证均能由格式正则识别出来，仍依靠低置信复核与支持范围约束；白/黑牌的最终拒绝顺序见3.2.3。

## 3.10 字符模型与训练方案

### 3.10.1 CharCNN、模板与HOG+SVM

| 模型 | 结构／训练方案 | 保存与加载 |
| --- | --- | --- |
| CharCNN | 输入1×32×32；两层Conv3×3-32/BN/ReLU后池化到16×16；两层Conv3×3-64/BN/ReLU后池化到8×8；一层Conv3×3-128/BN/ReLU后池化到4×4；Flatten2048→Dropout0.3→FC256→ReLU→Dropout0.3→FC65；约68万参数 | 推理仅state_dict，`weights_only=True`、CPU加载、eval |
| 模板 | 每类训练图float32均值；`TM_CCOEFF_NORMED`相关得分经温度softmax | 压缩npz，`allow_pickle=False`加载 |
| HOG+SVM | 324维HOG，RBF、C=10、gamma=scale；每类最多500，seed42；旧概率SVC兼容，新训练可加`--calibrated` | joblib；加载后验证65类顺序、324维输入和概率接口，仅使用本项目受信模型文件 |

`--calibrated`采用 `CalibratedClassifierCV(SVC(...), method="sigmoid", ensemble=False)`，交叉验证折数为`min(5,每类最少训练样本数)`；每类不足2个样本时报错。该路径避免启用旧SVC的 `probability=True` 参数；旧模型路径继续兼容，不能因弃用提示误报训练失败。

所有训练脚本保存后调用 `write_manifest_entry`，记录name、version、charset_sha、input_size、train_data、val_char_acc、sha256、created_at。加载器检查文件存在、登记记录、字符表哈希和登记的文件哈希，再按分类器构建模型；元信息字段存在不代表其所有值均由加载器逐项强校验。

### 3.10.3 混合来源与断点续训

训练模型、checkpoint、日志和计时文件相互独立。checkpoint默认同名 `.checkpoint.pt`，保存模型、优化器、余弦调度器、已完成轮数及Python/NumPy/Torch和采样生成器状态，用`weights_only=True`恢复。只支持epoch边界续训；`--epochs`为原计划总轮数，`--stop-after`控制本次最多执行轮数。数据目录、文件清单、大小、修改时间、超参数及来源权重不兼容时拒绝恢复，不能将推理state_dict当作训练断点。

下列命令是数据到位后的运行示例，不代表本次已训练或已达标。混合续训必须原样重复来源、权重、batch和总轮数；补充目录应只有train。

```powershell
.venv\Scripts\python.exe -m lpr_tools.train.train_cnn --data algorithm/data/chars --data algorithm/data/provinces_synth --data-weight 3 --data-weight 1 --epochs 15 --stop-after 2 --out algorithm/out/models/char_cnn_v1.pt --version char_cnn_v1
.venv\Scripts\python.exe -m lpr_tools.train.train_cnn --data algorithm/data/chars --data algorithm/data/provinces_synth --data-weight 3 --data-weight 1 --epochs 15 --resume algorithm/out/models/char_cnn_v1.checkpoint.pt --out algorithm/out/models/char_cnn_v1.pt --version char_cnn_v1

```

`manifest.train_data`以JSON字符串记录全部来源path/weight。新CNN计时为每轮训练和验证的累计时间，SVM计时为fit/校准时间，均不含数据读取和保存；不同口径须在比较中标明。历史模型未记录训练时间时显示N/A，不从文件时间推算。

## 3.11 多帧投票与重复抓拍判定

### 3.11.1 批量和流式投票

| 编号／接口 | 输入输出 | 参数 |
| --- | --- | --- |
| M2-PY-07 `vote(results,*,min_frames,min_confidence)` | 逐帧结果 → 新的投票或回退结果 | min_frames=2，min_confidence=0.80【待调】 |
| M2-PY-08 `PlateVoteSession.feed(result,ts)` | 单帧结果和单调秒时间戳 → 结果或None | agree_frames=3、window_s=2.0、min_frames=2 |
| M2-PY-09 `flush()`／`reset()` | 强制结算并清空／仅清空 | 流结束时flush，换车辆或车道会话时reset |

有效投票帧必须为OK或LOW_CONFIDENCE，长度为7/8且字符串、layout、逐位概率数量一致，概率有限且在[0,1]内。少于min_frames时返回置信度最高的有效单帧，frames_used=1；没有有效帧时保留首帧结果并标frames_used=0；空输入为BAD_INPUT。

```text
R = 有效结果
若没有R：返回首帧失败结果（空输入返回BAD_INPUT）
若有效帧总数不足min_frames：回退最佳有效单帧
L = R中layout众数；只保留长度L
对每一位i：
    weight_i(c) = 该位置识别为c的各帧char_confidences之和
    chosen_i = 权重最大字符；conf_i = weight_i(chosen_i)/同长度有效帧数
重新校验投票车牌；confidence = min(conf_i)
从该长度最高置信帧继承颜色、图像和几何
返回新车牌、状态、逐位置信度、frames_used及单个投票候选
```

众数和字符权重并列按首次出现顺序处理。min_frames在选择众数长度前检查，筛为同长度后不再次检查；不能把它描述为每种长度都必须达到2帧。投票不是“多数帧整牌相同”才接受，也不是给每帧confidence统一乘权；权重来自逐位置信度。`recognize_many`汇总各帧stage_ms并记录总体调用墙钟时间。

流式会话在锁内缓存帧。任一有效完整车牌字符串累计达到3次，或新feed时距首帧严格大于2.0秒，调用vote并清空状态；并非后台定时自动触发。时间戳非法或倒退会抛ValueError；该规则属于流式接口本身，不在recognize*的异常兜底承诺内。G3脚本结束时调用flush；每车道使用独立会话，避免把不同车辆帧混投。

### 3.11.2 重复抓拍判定

M2-PY-10：`DuplicateFilter.check(lane_id,result,ts)->(is_duplicate,reason)`。默认`dedup.window_s=30`秒【待调】、`dedup.dhash_max_hamming=10`【待调】。对象有锁，时间戳有限且整体单调；历史按lane隔离，仅OK/LOW_CONFIDENCE且有车牌的结果参与。

```text
清除age>30秒的记录（恰好30秒仍保留）
若结果状态无效或无车牌：返回False，不新增记录
若同车道窗口内存在相同车牌：返回(True,same_plate)
否则若编辑距离<=1，且双方校正图dHash均有效、汉明距离<=10：
    返回(True,similar_plate)
否则记录本次非重复观察，返回(False,空原因)
```

dHash将灰度图或BGR转灰度后缩为9×8，对相邻像素作“右值严格大于左值”的64次比较。缺失或非法图像不给相似性证据，但不影响同牌精确判重。重复命中不新增记录、不延长TTL；reset清空历史和时间戳。M2判定不能代替M3/M5的事务幂等与重复入场校验，相似判重也需业务侧选择复核策略。

## 3.12 数据集与测试集方案

### 3.12.1 数据来源、标签和字符样本

| 数据来源 | 计划用途 | 约束 |
| --- | --- | --- |
| CCPD2019 | 常规7位车牌及不同环境子集 | 人工取得数据后核实目录、标注和许可；不在本章宣称已到位 |
| CCPD2020 Green | 新能源8位车牌、槽位校准 | 原始split保留，使用GT四角点 |
| 本地标注图 | 独立本地评测、独立来源的省份补样 | 训练、验证与测试图片分开，课程内使用 |
| 字体／仿场景合成 | 流程冒烟、训练补样 | 正式测试和验证不混入；单独标记来源，不能证明实景准确率 |

CCPD文件名包含车牌字符下标、bbox和四角点等。解析器将原始RB、LB、LT、RT顺序转换为LT、RT、RB、LB；索引CSV的quad是8个空格分隔坐标，bbox为x、y、w、h。官方表中的O占位符或不支持标签须跳过，不能作为字母O训练。`ccpd_index.csv`生成器写绝对路径；使用其他相对路径索引时必须注意build_chars按`--raw`解析，而当前评测索引工具按索引CSV所在目录解析，建议统一使用生成器产出的绝对路径。

```text
先确定原图train/val/test划分，优先官方split
读index，只取has_plate=1、skip_reason为空的train/val行
剔除测试manifest列出的图；在写出前检查跨split同路径/相同文件内容
按GT quad校正到对应尺寸，按配置槽切位
unify_polarity → normalize_char → 输出字符PNG和标签索引
按类别上限在train/val间分配额度，打印并保存65类数量与截断统计
```

默认每类train+val合计上限8000【待调】，不是分别各8000；预算≥2且两边均有样本时至少各保留1，避免训练数据先耗尽验证额度。输出目录须为空，文件名附路径短哈希防同名覆盖。字符索引为`path,source_path,split,label,char,plate_no,position`，同时输出`chars_stats.json`。当前训练样本生成v0使用固定槽；运行时分割使用对齐后收紧框，两者存在分布差异，后续应加入真实分割样本并复核标签，不能宣称两种裁剪已完全一致。

```powershell
.venv\Scripts\python.exe -m lpr_tools.data.ccpd --raw algorithm/data/raw --out algorithm/data/index/ccpd_index.csv
.venv\Scripts\python.exe -m lpr_tools.train.build_chars --index algorithm/data/index/ccpd_index.csv --raw algorithm/data/raw --out algorithm/data/chars --exclude-manifest algorithm/testset/manifest.csv
```

测试清单应先冻结并排除，再生成正式训练字符。对另行补充的本地或合成训练目录，也须独立核查近重复图和来源，文件路径/字节相同检查不能发现所有视觉近重复。

### 3.12.2 测试清单与防泄漏

| 类别 | 目标数量 | 抽样／审查方法 |
| --- | --- | --- |
| clear | ≥150 | CCPD base官方test取120、CCPD2020 test取30；seed42 |
| night | ≥50 | ccpd_db亮度字段<40【待校准】并核实夜间标签；本地夜拍需独立标注 |
| tilt | ≥50 | ccpd_tilt／ccpd_rotate的test记录固定抽样 |
| dirty | ≥50 | blur／weather／challenge候选，保留待人工确认标记并审图确认污损属性 |
| local | ≥50，单列 | 全部独立本地测试图，不计上述300张 |
| np | 20，单列 | 无牌test记录，单独计算误检率 |

G2主集合为clear/night/tilt/dirty合计至少300张；local、np不得拿来凑主集配额。测试清单列为`path,plate_no,plate_color,category,source,quad,note`；相对path以清单所在目录解析，quad可空，但oracle评测要求有牌记录全部提供quad。10-29冻结v1后只追加并记录变化，不用test集调参。

```powershell
.venv\Scripts\python.exe -m lpr_tools.data.sample_testset --index algorithm/data/index/ccpd_index.csv --out algorithm/testset/manifest.csv --seed 42
```

抽样脚本仅从index的test记录选择CCPD样本，配额不足默认失败，不回借train/val。`--allow-shortfall`只供演示并报告缺额，不满足正式配额；本地样本仍应按目标另行补齐和核验。低亮度字段与子集名称只是筛选依据，不等价于已人工确认图像质量。

数据和视频放`algorithm/data/`，实验输出放`algorithm/out/`，不入库；正式清单版本化。模型只有经评审且满足大小约束的正式CNN权重才按项目安排纳入`algorithm/models/`，不把实验权重或训练断点误提交。

## 3.13 评测方法与验收口径

### 3.13.1 指标、测量边界与结果占位

| 指标 | 目标值 | 测量方法 | 当前结果 |
| --- | --- | --- | --- |
| G1 | CPU、1280×720单帧P95≤300ms | 保持比例补边；5次预热后100次recognize墙钟计时，输出P50/P95/max及各阶段统计 | 待 CCPD 数据到位后填写 |
| G2 | 清晰整牌≥95%；夜间、倾斜、污损分别≥85%；主集≥300张 | 各类别逐图比较完整车牌，未检出/分割失败均算错；local与np另报 | 待 CCPD 数据到位后填写 |
| G3 | 按媒体时间抽帧5fps识别；端到端吞吐≥15fps | 5分钟视频全部帧解码，吞吐=解码帧数/总墙钟秒数；含打开、解码、识别、投票和释放 | 待 CCPD 数据到位后填写 |
| G7 | 算法运行时核心包覆盖率≥60% | pytest-cov统计lpr，沿用根目录.coveragerc排除cli.py；lpr_tools不在覆盖源中 | 待 CCPD 数据到位后填写 |

本批按派工要求统一保留上述结果占位，不填写未执行的数值。G7覆盖率命令本身不依赖CCPD，可在无数据集条件下独立运行；统一占位不表示CCPD是其执行前提。

G1计时不包含图片读取与预先letterbox，也不是HTTP接口响应时间；候选回退阶段耗时累加。应记录CPU、线程数、模型版本、配置、数据清单、状态分布及commit，防止“快速失败”被误解为识别能力达标。

G2另报字符准确率=`逐位相等字符数/Σmax(真值长度,预测长度)`、自动通过率=`OK数/有牌总数`、自动通过精度=`OK且整牌正确数/OK数`，分母为0显示N/A。np误检率=`返回非空车牌的无牌图数/无牌图总数`。状态失败归因只是代理线索，不能直接宣称测得定位召回；独立Top-3定位召回以原图bbox IoU≥0.5判断，排除np。

G3的15fps分母是处理全部解码帧的墙钟时间，不是识别调用次数/秒，也不是要求识别每个源视频帧；脚本不会将同一解码帧重复识别来凑5fps。当前脚本的投票会话从默认`load_config()`读取阈值，应将该默认配置纳入评测记录。

### 3.13.3 三方法对比、oracle与消融

```powershell
.venv\Scripts\python.exe -m lpr_tools.eval.ablation --chars algorithm/data/chars/val --models cnn=algorithm/out/models/char_cnn_v1.pt template=algorithm/out/models/templates_v1.npz svm=algorithm/out/models/svm_v1.joblib --out algorithm/out/ablation
```

字符对比在同一字符集报告总体、省份和字母数字准确率、逐字符调用平均耗时、模型大小、已记录训练耗时；每模型5次单字符预热，I/O和模型加载不计时。它不同于8字符批量延迟及G1整帧延迟，不能混用。整牌结果由 `eval_accuracy`另行评测并通过`fill_plate_accuracy`回填，当前字符对比脚本不自动完成去CLAHE、去透视、去位置约束或去候选回退的整牌消融。

## 3.14 风险与预案

| 风险 | 判断依据／触发条件 | 预案与责任边界 |
| --- | --- | --- |
| 数据迟到 | 原图、官方split或测试视频不齐 | 先用自造小样本验证契约，真实指标保留占位；由tonyswift868协调数据、贺锦晗协调视频 |
| 省份分布偏斜 | 验证错误集中于少数省份 | 独立补充训练样本、来源加权及增广；省份先验仅在验证有效后启用，不使用本地test调参 |
| 定位误检／夜间偏色 | 独立定位召回、候选图和失败状态 | 调整ROI、颜色及面积参数；保留边缘分支和候选回退，逐项验证 |
| 槽位与裁剪偏差 | 粘连、截断、8位分割失败集中 | 用CCPD真值校正图校准槽位，补入真实分割字符；保留【待校准】标记 |
| G1超限 | 正式CPU基准P95>300ms | 定位阶段耗时分解，尝试ROI、降低工作宽度或候选数、调整线程；同步重测G2防止性能优化牺牲准确率 |
| 难例目标未达 | 11-01检查点验证集难例准确率<75% | 按既有K1预案评审自训练轻量四角点网络或CRNN+CTC兜底；须组长同意并更新设计，当前均未接入 |
| 测试泄漏 | 同源图跨split、近重复图、冻结集参与调参 | 整图先划分、路径/内容检查、人工近重复检查，test只用于报告 |
| 低置信／特殊车牌 | 不支持字符、弱图像或异常输出 | 依状态转人工，保留抓拍图与候选证据；不得绕过业务放行校验 |
| 接口／版本不一致 | 模型表哈希不符、M3字段或配置变化 | 启动校验、版本追溯、契约测试；变更经架构师协调，不擅改冻结结构 |
| 识别重复 | 同车多帧、多次抓拍或近似车牌 | 每车道会话、时间窗过滤；M3/M5仍执行数据库幂等，不能仅靠图像去重 |
