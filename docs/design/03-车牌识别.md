## 3.1 模块职责与边界

M2 识别部分提供进程内 Python 包 `lpr`，从入场、出场抓拍图或同车视频帧中提取车牌信息，返回状态、置信度和图像证据。保留“预处理、定位、校正、分割、识别、后处理”的阶段编号；分割仅属于 S 路，校正后的整牌识别 R 路与原框读牌 B 路不依赖分割成功。当前默认已启用三路，并非仍处于四角点网络加分割单路的初稿状态 [配][接]。

| 需求／协作项 | 本模块职责 | 其他模块职责 |
| --- | --- | --- |
| R1、FR-01、FR-02 | 图像识别、候选与状态输出 [规] | 采集层提供图片、视频及车道信息 |
| E1 | 低置信、无牌及异常状态，保留可复核猜测 [接] | M3/M6 人工录入、改牌与原抓拍图保存 |
| E7 | 同车多帧聚合与重复抓拍判定 [规] | M3/M5 停车会话及事务幂等 |
| G1/G2/G3/G7 | 提供时间、准确率、吞吐和核心包覆盖口径 [规] | M8 组织系统级验收与视频回放 |
| 对外调用 | `PlateRecognizer`、`PlateVoteSession`、`DuplicateFilter` [接] | M3 对接既有入场、出场抓拍接口 |
| 持久化与放行 | 返回车型提示及识别证据 [接] | 业务层建档、计费、缴费与放行；`OK` 不直接等于允许放行 |

运行时使用本地 OpenCV、NumPy、PyTorch 等已有依赖，不调用外部识别服务、不使用车牌专用现成权重。检测器和框读骨干使用通用 ImageNet 初始化；字符、序列输出头及本地车牌任务由项目训练。推理面向 CPU，离线训练设备不构成接口要求 [检][识]。

## 3.2 对外接口与数据契约

### 3.2.1 PlateRecognizer 调用接口

以下签名与调用约定来自 `docs/M2-接口说明-M3.md` 及当前 `pipeline.py` [接][流]。

| 编号 | 接口 | 输入及输出 | 约定 |
| --- | --- | --- | --- |
| M2-PY-01 | `PlateRecognizer.from_config(path=None, **overrides)` | TOML 路径及覆盖项 → 识别器 | 加载模型、manifest、字符表与 SHA；初始化失败抛 `ConfigError` / `ModelLoadError` |
| M2-PY-02 | `warmup()` | 无业务输入 → `None` | 服务启动时预热，避免请求首次加载 |
| M2-PY-03 | `recognize(image, *, lane_id=None, debug=False)` | 单张 BGR `uint8` → `RecognitionResult` | 接受灰度或单通道图并转 BGR；按车道应用 ROI |
| M2-PY-04 | `recognize_bytes(data, *, lane_id=None)` | JPG/PNG 字节 → 同一结果类型 | 解码错误为 `BAD_INPUT`；耗时包含解码，阶段增加 `decode` |
| M2-PY-05 | `recognize_many(images, *, lane_id=None)` | 同车图像／字节序列 → 聚合结果 | 建议同车一次 1—5 帧 [接]，不是强制数量上限；空序列为 `BAD_INPUT` |
| M2-PY-06 | `version` | 只读版本串 | 当前模型组合包含分类器、检测器、R 与 B 版本 [配][流] |

配置加载优先级为默认值、显式文件或 `LPR_CONFIG`、调用覆盖项；覆盖项用双下划线表示分组，例如 `runtime__classifier`。M3 只需在启动时构造和预热一次，在异步后端用线程池或 `asyncio.to_thread` 调用同步识别。当前 Torch 线程数为 2 [配]；更换某个模型还需匹配 manifest，不凭文件名自动替换其余模型。

### 3.2.2 RecognitionResult

字段及空值语义以当前 M3 接口文档为准 [接]；`to_dict()` 不添加仲裁内部诊断字段。

| 字段 | 类型／含义 | 约定 |
| --- | --- | --- |
| `status/error_code/message` | 状态、业务码及提示 | 业务按状态分支，不只判断是否有字符串 |
| `plate_no/plate_color/layout` | 车牌、颜色及字符数 | 无读法可为 `None`；常规长度为 7/8 [规] |
| `confidence/char_confidences` | 选中路线的整牌／逐字符置信度 | 原路线整牌值通常为最小字符置信度；自动同串对保留左路线原整牌值，手动共识按规则取两路最小值 [仲]；不是正确概率保证 |
| `candidates` | 备选文本与选择分 | 单帧默认 Top-3 [配]；不是三个路线的票数，多帧通常只保留投票结果 [接] |
| `bbox/corners` | 原图框及 LT、RT、RB、LB 四点 | 框为 `(x,y,w,h)`；无几何时为空 [接] |
| `plate_image` | 选中路线的图像证据 | S/R 为校正图，B 为原框外扩 crop [流]，不能一概称为透视校正图 |
| `elapsed_ms/stage_ms` | 总墙钟及累计阶段耗时 | 单位 ms；候选／视图重复尝试累加 [流] |
| `frames_used/model_version/debug` | 聚合帧数、版本与可选调试图 | 调试 ndarray 和 `plate_image` 不进入 `to_dict()` [接] |
| `vehicle_type_hint` | small/large/unknown | 只供业务参考，不代替车辆档案及收费规则 [接] |

路线、候选与视图索引供实现核验，仍不扩展既有公共 JSON 字段。对外置信度与 beam 内归一化候选分须分开使用 [仲][接]。

### 3.2.3 状态与错误码

下表数字为固定接口码，非评测成绩（来源：[接] 状态表）。

| 状态 | 码 | 触发／返回特点 | M3/M6 处理 |
| --- | ---: | --- | --- |
| `OK` | 0 | 三路自动规则已接受 | 继续业务校验 |
| `NO_PLATE` | 3001 | 融合候选为空 | 人工录入或重新抓拍 |
| `LOW_CONFIDENCE` | 3002 | 合法读法只供人工复核 | 预填猜测，人工确认 |
| `SEG_FAILED` | 3003 | 有候选但最终无可用读法 | 人工录入；不等于只有 S 分割失败 |
| `INVALID_FORMAT` | 3004 | 最终保留非法格式读法 | 人工确认或改牌 |
| `BAD_INPUT` | 3005 | 图像、编码、ROI 或尺寸无效 | 重新抓拍／检查上传 |
| `UNSUPPORTED` | 3006 | 未自动通过，首候选首校正视图为白／黑 | 特种牌转人工 |
| `INTERNAL_ERROR` | 3099 | 未预期阶段异常 | 记录日志并转人工 |

自动 `OK` 先返回；白／黑门禁作用于未自动通过后的结果，不写成校正后无条件先拒绝。三路未自动通过时，合法回退维持 `LOW_CONFIDENCE`，不能因为旧双路曾给过 `OK` 就升级为自动接受 [仲][流]。

## 3.3 六阶段总体流程

![图 5 车牌识别六阶段流水线](docs/img/pipeline.png)
（draw.io 源文件：docs/img/src/pipeline.drawio）

图 5 沿用规定路径 [规]。既有图源的候选／视图流程仍适用，但 R/B 节点保留了旧版本标签，交稿前需按本章更新为 crnn_v4 / box_reader_v3 后由用户导出PNG；本批白名单不含图源与PNG [派]，未改图，也未把图片当作已同步。S 表示分割加 CharCNN，R 表示校正 CRNN，B 表示原框 BoxReader；三路在同一候选身份下组合。

| 阶段 | 输入 | 当前默认输出／衔接 |
| --- | --- | --- |
| 1 预处理 | 原图、车道 ROI | 工作 BGR、增强灰度、HSV、scale 和 offset；原图仍供网络检测和裁片 [配][流] |
| 2 定位 | 原图供 plate_det_v1，工作图供传统定位 | 网络优先、传统补位的融合候选，不是纯网络候选 [流] |
| 3 校正与框裁片 | 当前候选及原图 | 有序透视视图供 S/R；原 bbox 外扩 crop 供 B、每候选读取一次并缓存 [流][裁] |
| 4 分割 | 当前校正视图及长度假设 | 仅 S 路产生字符格；失败不阻断 R/B [流] |
| 5 识别 | 字符格／校正整牌／原框 crop | S/R/B 各自文本、逐字概率与置信度，保留候选／视图身份 [识][流] |
| 6 后处理 | 同候选的路线读法与预测角点 | 011 自动早返回；耗尽后业务门禁和 T20_A 人工回退 [配][仲] |

```text
校验原图与ROI；预处理无效 → BAD_INPUT
传统候选 = locate(工作图)
网络候选 = plate_det_v1.detect(原图)，按候选中心过滤车道ROI
候选 = 网络优先合并传统补位、IoU去重；为空 → NO_PLATE
按融合顺序逐候选：
    生成该候选的有序校正视图
    B = 原候选bbox经crop_box外扩后读取一次，缓存于该候选
    按原序逐校正视图：
        S = 按版式顺序分割、CharCNN解码；首个S自身OK结束版式尝试
        R = 对该视图做CRNN读取（S失败也执行）
        011：同视图S/R → S/B → R/B；再S-solo → R-solo
        首个满足自动规则的事件 → 立即返回OK，不再读后续视图/候选
    全部视图结束后，才检查该候选B-solo；通过 → 返回OK
自动搜索耗尽：先检查首候选首视图白/黑业务门禁 → UNSUPPORTED
否则按候选0预测角度选T20_A偏好，再按固定顺序选择合法人工读法
有合法读法 → LOW_CONFIDENCE；无读法 → INVALID_FORMAT或SEG_FAILED
单帧返回RecognitionResult；同车多帧由调用方选择投票和去重
```

这里“S 自身 OK”只结束该视图的长度尝试，随后仍读 R 并仲裁；它不是整个系统的早返回条件。B 不跨候选投票，同串对不跨 S/R 校正视图拼接；未出现自动事件时才进入全局人工回退 [仲][流]。

## 3.4 阶段一：预处理

**输入／输出：** 原图、`PreprocessConfig`、可选原图 ROI → `PreprocessOut`。BGR、灰度及单通道 `uint8` 的输入检查、ROI 求交、等比例缩小与坐标映射沿用现实现。工作坐标为 `(原图坐标-offset)×scale`，NumPy 访问顺序为 `[y,x]` [流][裁]。

**处理步骤：** 校验图像与 ROI；灰度转 BGR；裁取 ROI 并记 offset；只缩小、不放大；灰度执行 CLAHE 和 GaussianBlur；HSV 从工作 BGR 转换。该工作图供传统定位，不先将原图强制缩到工作宽度再送 plate_det_v1 [流]。

| 参数 | 当前值 | 出处及限制 |
| --- | --- | --- |
| `min_side` | 120 px | [配] preprocess；原图与 ROI 均校验 |
| `work_width` | 800 px | [配] preprocess；工作宽度上限 |
| `clahe_clip/clahe_grid` | 2.0 / 8 | [配] preprocess |
| `blur_ksize` | 5 | [配] preprocess；正奇数 |
| `[lanes]` | 空 | [配]；无车道 ROI 时用全图 |

**失败情形：** 空图、错误通道或类型、尺寸不足、ROI 无交集等受控输入错误返回 `BAD_INPUT`；其他未预期错误走统一异常兜底。输入图不就地修改 [流]。

## 3.5 阶段二：车牌定位

**输入／输出：** plate_det_v1 直接接收原图，其内部 RGB 等比例补边和归一化；传统定位接收工作灰度／HSV。两者均输出原图 bbox、角点和分数。当前 `runtime.corner_model_path` 虽保留旧键名，实际指向 `models/plate_det_v1.pt`，按 checkpoint 架构分派加载 [配][检]。

**处理步骤：** 网络以独立中心、框和角点头产生候选；传统分支继续使用颜色与 Sobel 边缘、形态学、轮廓和几何评分。运行时先取得传统候选，再取得网络候选；融合顺序仍为网络在前，传统在后，达到上限即停止，不用两个来源的分数重新全局排序 [流]。

```text
net = 原图网络候选；根据bbox中心保留ROI内项
classic = 工作图传统候选，坐标反算至原图
依次遍历net，再遍历classic：
    若与已选任一框重叠达到融合门槛：不重复加入
    否则保留；达到候选上限即结束
```

| 参数／规则 | 当前值 | 来源 |
| --- | --- | --- |
| detector 输入、分数阈值 | 384×384；0.25 | [配] runtime、[C17] §1、[检] §3.1；分数阈值未变 |
| detector 内部 NMS | IoU 0.5 | [检] 3.1；与传统及融合 NMS 分开 |
| 融合去重／候选上限 | IoU≥0.5；最多 3 | [流] `_merge_candidates`、[配] runtime |
| 传统宽高比／面积比 | 2.0—5.5；0.001—0.08 | [配] locate |
| 传统倾角／行跳变满分参考 | 30° / 20 | [配] locate；跳变参考不是独立硬拒绝 |
| 传统闭核／NMS | `[0.022,0.006]` / 0.3 | [配] locate；闭核按实际工作图宽度生成 |

**失败情形：** 融合为空才是 `NO_PLATE`。检测器“无候选”不等于系统无牌，因为当前仍有传统补位。第十二批独立实验提出去掉常规融合及必兜底的建议，但当前默认没有实施；本章按实际配置记录，不把建议写成既成行为 [B12][流]。

## 3.6 阶段三：透视校正与原框裁片

**输入／输出：** 原图与当前候选 → 有序 `RectifiedPlate` 视图及 B 路原框 crop。几何均从原图取样，透视矩阵为原图到校正图的映射 [裁]。

网络角点提供初始透视和几何先验；在候选附近生成有界颜色／边缘轮廓、像素证据支持的精修假设，绿色边界拟合只补充候选。`rectify_candidates()` 的首视图与 `rectify()` 一致，网络原四角保留在视图池内；最多保留 4 个有序视图（来源：`rectify.py:rectify_candidates` [裁]）。排序只读像素与几何，不读标签、不按识别真值选视图。`deskew_vertical` 仍是独立可选能力，未在默认链另插错切搜索。

| 参数／输出 | 当前规格 | 来源 |
| --- | --- | --- |
| S/R 校正尺寸 | 7 位 252×80；8 位 276×80 | [配] rectify、[裁] `_finalize_warp` |
| 候选外扩 | 每侧比例 0.10 | [配] rectify |
| 不确定版式 | `layout=0`，后续按长度假设尝试 | [裁][流] |
| B 路 crop pad | 水平 0.08、垂直 0.12 | [识] §3.2、[C17] §2；从框读权重读取 |
| B 路模型输入 | RGB 192×64 | [识] §3.2、[模]；crop 后由 reader 缩放归一化 |

B 路统一调用 `crop_box`，仅裁原图轴对齐框并外扩，不做外部透视校正；内部 STN 是框读网络的一部分。先为当前候选读取 B 并缓存，在各透视视图复用；不能每个视图重跑 B，更不能用 GT 框替换运行时检测框 [流][裁]。

**失败情形：** 无效几何或裁片异常走既有异常处理；像素精修不足时用已有几何候选回退。S/R 视图可能仍截断字符，B 也无法恢复框外已丢失的信息；三路没有“任一分割失败就整体失败”的规则 [流][识]。

## 3.7 阶段四：字符分割（S 路）

**输入／输出：** 校正图、颜色及当前长度假设 → 字符框、归一化字符图与 `SegmentResult`。字符框位于校正图坐标，不与原图 bbox 混用 [裁]。

**处理步骤：** 极性统一、二值化、字符带定位、边框及小连通域清除；用已校准槽位搜索平移和缩放，收紧墨迹框，校验几何与覆盖；调用共享 `normalize_char` 生成字符格。不把步骤写成独立铆钉检测器或已实现投影谷切字 [裁]。

| 参数／规则 | 当前值／行为 | 来源 |
| --- | --- | --- |
| 输出字符尺寸 | N×32×32 `uint8`，N 为 7/8 | [配] segment、[识] |
| `binarize` | otsu；另支持 adaptive | [配] segment |
| 七位槽中心／宽度 | `[0.075397,0.204365,0.380952,0.507937,0.636905,0.763889,0.894841]` / 0.103175 | [配] segment 校准注释 |
| 八位槽中心／宽度 | `[0.076087,0.193841,0.378623,0.489130,0.599638,0.710145,0.818841,0.927536]` / 0.094203 | [配] segment 校准注释 |
| 版式尝试 | 已知长度优先；未知按 7、8；yellow/unknown 可追加另一长度 | [流] `_layouts_to_try` |

**失败情形：** 空槽、截断、墨迹／覆盖不足及几何异常返回 `ok=False`。`quality` 是诊断质量，不是整牌概率，不再乘入分类置信度。分割失败继续 R；S 自身首个解码 `OK` 只结束该视图版式循环，随后仍做三路仲裁 [流]。

## 3.8 阶段五：三路车牌读取

以下为当前默认权重职责，不能把新候选模型的训练目标写成默认模型结果（来源：[配][识]）。

| 路线 | 输入表示 | 输出及依赖 |
| --- | --- | --- |
| S：char_cnn_v2 | 分割后的 N×32×32 灰度格 | N×65 类概率，位置约束组成文本；字符表为 31 省、10 数字、24 字母，不含 I/O [识][规] |
| R：crnn_v4 | 当前透视校正整牌，内部灰度缩放为 160×40 | CNN + BiGRU + CTC；输出整串及逐字置信度，65 字符加 blank [识] |
| B：box_reader_v3 | 原 bbox 外扩 crop，RGB 192×64 | STN + MobileNetV3 前段 + 高度注意力 + BiGRU + CTC；输出整串与逐字置信度 [识] §3.2 |

S 的概率保留原 softmax，限制可选字符时不重新归一化；R/B 贪心 CTC 去 blank、合并连续重复后再验证长度及版式。R/B 不输出可直接替代字符分割的字符框；B 的 crop 与 R 的透视校正图不能互换。概率温度随已登记权重，不在运行时临时按图拟合 [识][流]。

**失败情形：** 空读、长度错误或不合法格式不参与合法共识；S 的失败不阻断 R/B。模型缺失、SHA／字符表／结构不匹配在初始化时报错；运行期异常由统一兜底返回状态。网络细节、训练数据与量见 3.10。

### 3.9.2 T20_A 人工回退与业务投影

A：从所有同视图合法同串 S/R 对中取最小置信度最高者，保留 R 身份；无配对取最高合法 R。M：按候选／视图顺序找首个合法同串对，配对顺序仍为 S/R、S/B、R/B，输出左路线及两路最小置信度；无共识则最高合法 B，再最高合法 R。L：复放旧 S/R 自动与手动读法，仅作为本次人工候选来源。所有最高值只在严格大于时更新，同分保留先项 [仲] §3、§7.3。

```text
若已有新自动OK：原样返回
仅取融合候选0的预测LT/RT/RB/LB，不读取GT或文件名角度
angle = 顶边和底边方向角绝对值的平均；缺失或非有限 → 无角度
preferred = A（angle达到倾角门槛时），否则M
按 [preferred, A, M, L] 取首个存在的合法读法
未自动通过且首候选首视图白/黑 → UNSUPPORTED
合法人工读法 → LOW_CONFIDENCE；没有时保留INVALID_FORMAT或SEG_FAILED
```

倾角门槛为 20.0°，配置 `nonok_fallback="predicted_tilt_then_corrected"`（来源：[配]、[仲] §7.3）。无角点走 M，不改用真值或其他候选角度。L 即使包含旧自动 `OK`，也不能新增三路自动接受。自动通过后的车型提示仍由版式与颜色给出，业务层独立决定放行 [仲][接]。

### 3.9.3 阈值来源与 fit/hold 选法

第十七批复用既有开发 val1000 与 devhard2100 的内容隔离分半：按规范路径排序、`Random(42)` 分层打乱，同内容 SHA 归并到同半区；每半 val500、hard1050、green250，内容交叉为零（来源：[仲] §5/§7.5、[C17] §2）。它们是开发集 fit/hold，不是冻结 G2 测试集。

最终四阈值来自第十七批预注册的四轴精确搜索和全集收紧，不能沿用早期“只在 fit 选定全部默认”的描述。先以 agree、B、S、R 四轴在 fit 上最大化接受数，约束 val/hard 两组均非空且自动精度≥99.5%；整数判定为 `correct×200≥accepted×199`，不舍入、不加容差。agree/B 取 fit 边界及 0/1，S/R 另允许 `nextafter(1,+inf)` 作为关闭哨兵（来源：[C17] §2及评分前协议补充）。

fit 初选在 hard 全集未达门槛，遂按事前写定的 agree→B→S→R 顺序逐轴上升一个 fit 边界，每步核对两全集，首次同时达标即停止；共538步，最终精确值见3.9.1（来源：[C17] §2）。011 与 T20_A 规则族保持冻结，本批没有重新选择回退规则。全集已参与开发准入，hold 也因此只能作为开发诊断；其两组仍低于99.5%，见3.13.2，不能称独立盲测或隐去风险 [C17]。

## 3.10 神经网络与训练方案

### 3.10.1 plate_det_v1：独立框与辅助四角点

骨干为通用 ImageNet 初始化的 ResNet18 stem 和 layer1—layer3；从 stride 8/16/32 特征构建 64 通道 FPN，中心热图、中心偏移与 log 宽高的框头、相对四角点头并行输出。共 2,829,709 参数；训练输入 288×288，当前默认推理输入 384×384（来源：[检] §3.1、[B11]、[配]、[C17] §1）。框直接回归，不由角点包围盒替代；角点无效时可由有效 bbox 构造矩形角点保留候选。

中心使用 Gaussian focal loss，框使用 SmoothL1 和 GIoU，角点使用辅助 SmoothL1；NP／框外背景只贡献负热图。训练池 213,043 张路径／内容唯一图，含 NP2,400；NP 经排除后按 seed42 划 train2,400/val601，另隔离 hard2,100，训练图框外背景继续作负例。完成 40 个全池 epoch、8,521,720 次池曝光（来源：[B11]、[检] §3.3）。训练排除规则见 3.12；共享索引不改。摄像头尺度实验中的 plate_det_v2 是对照，未进入当前默认 [配][B12]。

### 3.10.2 char_cnn_v2：逐字分类

CharCNN 输入为归一化灰度字符，卷积通道依次 1→32→32→64→64→128，池化后展平，分类层 2048→256→65；分类头产生 logits，推理转为 softmax 类概率（来源：`algorithm/lpr/recognize/cnn_model.py:CharCNN`、[识] §3.4）。监督为字符交叉熵，来源含 GT 四角校正与实际候选视图经正式 segment 产生的字符、绿色 train-only 分片及训练用字体省份辅助 [A6]。训练与推理共享字符归一化，不能只用固定槽训练再把收紧框推理误当同一分布。

第六批实验依次完成初始 15 轮、FT1 实际 1 轮、FT2 实际 2 轮；最终选 FT2 第 1 轮并作开发集单温度后校准（来源：[A6] 训练链与最终决策）。FT2 每抽样轮 131,072 draw 是有放回抽样，不是新独立原图数（来源：[A6]）。该历史版本按当时协议排除测试清单与金样例，并使用开发集作候选／温度选择；不能追溯声称它从未接触任何后来的开发名单。

### 3.10.3 crnn_v4：校正整牌序列识别

输入是透视校正后的 BGR 整牌，内部转灰度、缩放到160×40并归一化。CNN 提取特征，高度均值池化成宽度序列，BiGRU 加线性 CTC 头输出字符及 blank；不需要逐字符框标签。参数218,474（来源：[识] §3.3/§3.7、[模] crnn_v4 条目），输入表示与3.8一致。

v4 从自有 crnn_v2 续训，完成15个完整 epoch，选择第13轮；学习率8e-5，登记温度1.0862330198287964（来源：[识] §3.3/§3.7、[模] training_proof/calibration_temperature）。每轮覆盖210,564个真实 source 与73,697个在线合成输入，累计真实物理读取3,158,460次、合成1,105,455次（来源：[识] §3.5）。真实训练底图与首字替换分支分别记账，不把合成次数称为独立实拍图片；训练目标为整串CTC，隔离与省份面板边界见3.10.5。

### 3.10.4 box_reader_v3：原框直接读取

原 bbox 按权重 pad 裁片，RGB192×64 输入经低分辨率仿射 STN、MobileNetV3-Small 首卷积与前三残差块、Conv96/160 和 GroupNorm、高度注意力、BiGRU及CTC头。STN 推理只看像素，训练才用 GT 相对几何作辅助 MSE；参数544,401，pad=(0.08,0.12)（来源：[识] §3.2/§3.7、[模]）。仿射 STN 不等价于完整透视恢复。

v3 从自有 box_reader_v2 续训，完成20个完整 epoch，选择第18轮；主学习率8e-5、STN学习率1.6e-5、几何MSE权重1，登记温度1.1661430597305298（来源：[识] §3.2/§3.7、[模]）。每轮覆盖210,564个真实 source 与73,697个在线合成输入，累计真实物理读取4,211,280次、合成1,473,940次（来源：[识] §3.5）。沿用分组 multiplicity 并补有限外省真实重放，同一 source 的逻辑重复折叠为损失权重，不等于额外独立增强。

### 3.10.5 省份均衡与当前权重边界

## 3.11 多帧投票与重复抓拍判定

### 3.11.1 批量与流式投票

`recognize_many` 对同车每帧执行完整三路，再按逐位置信度投票；它不是把同图 S/R/B 再当视频帧投票。`PlateVoteSession.feed(result,ts)` 支持流式聚合，结束显式 `flush()`，换车重置。每车道独立会话，不能将连续不同车辆混在同一窗口 [接][规]。

| 编号／参数 | 当前值／约定 | 来源 |
| --- | --- | --- |
| M2-PY-07 `vote(...)` | 有效帧为 OK／LOW_CONFIDENCE；字符与长度一致 | [规] 多帧节、[接] |
| M2-PY-08 `feed(...)` | `agree_frames=3`、`window_s=2.0`、`min_frames=2` | [配] voting |
| M2-PY-09 `flush()/reset()` | 结束结算／清空 | [规]、[接] |

有效帧不足时可回退最佳单帧；`frames_used` 是实际参加同长度聚合的帧数，不一定等于上传数。时间戳须单调，会话不会后台自动计时触发，需后续 feed 或 flush。聚合置信度来自逐位权重，不能解释为多帧必然正确 [规][接]。

### 3.11.2 重复抓拍判定

M2-PY-10 `DuplicateFilter.check(lane_id,result,ts)` 返回是否重复及原因，按车道隔离。当前窗口30秒、dHash最大汉明距离10（来源：[配] dedup）。同牌直接命中；近似文本还需图像哈希支持，无图像不能提供相似证据。该提示不自行丢弃业务事件，也不代替数据库事务幂等 [接][规]。
