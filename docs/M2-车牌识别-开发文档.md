## 3 难度评估与总体策略

### 3.1 难度判断

整体难度：**中等**。流水线本身工程量不大（核心代码约 2—3 千行 Python），难点集中在三处：

| 难点 | 原因 | 影响指标 |
| --- | --- | --- |
| 难例准确率 | 传统定位与投影分割在夜间、倾斜、污损图上明显掉点，而 G2 要求难例 ≥85% | G2 |
| 数据分布偏斜 | 公开数据集 CCPD 采自合肥，省份字绝大多数是“皖”；演示如果用本地“陕”牌，省份字容易认错 | G2、演示 |
| 时间 | 剩余约 3 周：10-30 交详细设计，11-06 集成测试 | 全部 |

结论：做到“清晰图能跑通、准确率高”不难；做到难例 85% 需要尽早建好评测集、每天跑分、按失败原因定向优化。

### 3.2 策略

1. **契约先行**：第 0 天冻结数据结构与调用接口，同时给 M3 提供 FakeRecognizer，前后端不必等算法。
2. **评测先行**：测试集与评测脚本 10-29 前冻结；调参只看验证集，测试集只用于出报告，避免对测试集过拟合。
3. **失败归因**：CCPD 自带四角点标注，可用“真值定位”（oracle）模式把每个错误归到定位、分割或识别阶段，按损失最大的阶段派单。
4. **场景先验**：停车场摄像头位置固定，支持按车道配置 ROI，缩小定位搜索范围。
5. **候选回退**：定位保留前 3 个候选，前一个识别失败就自动试下一个。
6. **位置约束解码**：按车牌版式限定每一位允许的字符（首位只可能是省份字），从结构上消除一部分“0/D、8/B”类混淆。
7. **多帧投票**：视频场景下对同一车辆的多帧结果逐位加权投票。
8. **预案**：11-01 检查点若验证集难例准确率 <75%，启用 Plan B（第 14 章 K1）。

## 4 总体设计

### 4.1 识别流水线

```text
图像 BGR（任意尺寸，典型 1280×720）
  │
  ├─[1 预处理]  校验 → 车道 ROI 裁剪 → 缩放到工作宽度 800 → CLAHE 灰度 + HSV
  ├─[2 定位]    颜色分支（HSV 掩膜）+ 边缘分支（Sobel-x）→ 形态学 → 轮廓 → 几何过滤 → 打分 → NMS → Top-3 候选
  │             （候选坐标换算回原图）
  ├─[3 校正]    在原图上精修四角点 → 透视变换 → 7 位 252×80 / 8 位 276×80 → 颜色判别
  ├─[4 分割]    极性统一 → 二值化 → 去铆钉与边框 → 版式模板对齐 + 投影细化 → N 个字符框 → N×32×32 字符图
  ├─[5 识别]    CharCNN 批量推理（可切换为 模板匹配 / HOG+SVM）→ N×65 概率矩阵
  └─[6 后处理]  按版式位置约束解码 → 正则校验 → 置信度 → Top-3 备选 → 状态码
  │
RecognitionResult（车牌号、颜色、置信度、逐位置信度、四角点、校正图、耗时、状态）
  │
  ├─（多帧）逐位投票 → 最终结果
  └─（可选）DuplicateFilter 判断是否重复抓拍
```

### 4.2 六阶段输入输出与耗时预算

| 阶段 | 文件 | 输入 | 输出 | 耗时预算（P95） | 负责 |
| --- | --- | --- | --- | --- | --- |
| 1 预处理 | `preprocess.py` | BGR 原图、车道 ROI | `PreprocessOut` | 20 ms | 员工 B |
| 2 定位 | `locate.py` | `PreprocessOut` | `list[PlateCandidate]`（≤3 个，原图坐标） | 80 ms | 员工 B |
| 3 校正 | `rectify.py` | 原图 + 候选 | `RectifiedPlate` | 10 ms/候选 | 员工 B |
| 4 分割 | `segment.py` | `RectifiedPlate`、版式 | `SegmentResult`（N×32×32） | 15 ms/候选 | 员工 B |
| 5 识别 | `recognize/*.py` | N×32×32 | N×65 概率 | 10 ms/候选 | 员工 A |
| 6 后处理 | `postprocess.py` | 概率、版式、颜色 | 车牌号、置信度、状态 | 2 ms | 员工 C |
| 合计 | `pipeline.py` | — | `RecognitionResult` | 单候选约 140 ms；3 候选全回退约 250 ms，≤300 ms | 架构师 |

### 4.3 三种调用形态

| 形态 | 方法 | 场景 | 说明 |
| --- | --- | --- | --- |
| 单帧 | `recognize(image)` | 图片上传、岗亭手动抓拍 | 默认形态 |
| 多帧 | `recognize_many(images)` | 抓拍接口一次上传同一车辆的多张图（1—5 张） | 内部逐帧识别再投票 |
| 流式 | `PlateVoteSession.feed(result, ts)` | 视频回放（G3）、模拟摄像头 | 一致帧数够了或超时后输出一次 |

### 4.4 候选回退与多版式尝试

```text
best = None
for cand in candidates[:max_candidates]:                 # 按得分降序
    rect = rectify(image, cand)
    layouts = [rect.layout] if rect.layout else [7, 8]
    if rect.color in {yellow, unknown}: 追加另一种版式    # 黄绿双拼的大型新能源可能被判为黄色

if (best is None or best.status != OK) and candidates and candidates[0].color in {white, black}:
    return UNSUPPORTED                                    # 白牌、黑牌等特种车牌，暂不支持（已确认 Q12）
return build_result(best) if best else (SEG_FAILED if 有候选 else NO_PLATE)
```

## 5 对外接口契约（Phase 0 冻结）

**冻结规则**：本章内容 10-25 冻结。之后任何改动需架构师确认、当天通知刘一凡（M3）、同步更新 FakeRecognizer，并在文末“修订记录”登记。原则上**只加字段，不改不删**。

### 5.1 Python 调用接口

```python
# algorithm/lpr/__init__.py 对外导出
from lpr import PlateRecognizer, RecognitionResult, RecogStatus, DuplicateFilter, PlateVoteSession

class PlateRecognizer:
    @classmethod
    def from_config(cls, path: str | None = None, **overrides) -> "PlateRecognizer":
        """加载配置与模型。模型缺失或字符表哈希不匹配时立即抛 ModelLoadError（启动即失败）。
        path 为空时先读环境变量 LPR_CONFIG，再缺省为 algorithm/config/default.toml。"""

    def warmup(self) -> None:
        """用空白图跑一遍，消除首帧延迟。应用启动时调用一次。"""

    def recognize(self, image: np.ndarray, *, lane_id: int | None = None,
                  debug: bool = False) -> RecognitionResult:
        """单帧识别。image 为 BGR uint8。debug=True 时 result.debug 带各阶段中间图。"""

    def recognize_bytes(self, data: bytes, *, lane_id: int | None = None) -> RecognitionResult:
        """jpg/png 字节流，便于直接接 FastAPI UploadFile。"""

    def recognize_many(self, images: Sequence[np.ndarray | bytes], *,
                       lane_id: int | None = None) -> RecognitionResult:
        """同一车辆的多帧（元素可为 BGR 数组或 jpg/png 字节），内部逐帧识别后投票。"""

    @property
    def version(self) -> str:
        """例如 "lpr-1.0.0+char_cnn_v1"，写入日志与结果。"""
```

约定：`recognize*` **永不抛异常**，任何错误都通过 `status` 与 `error_code` 返回，满足《说明》第 9 章“单模块异常不影响主流程”。只有 `from_config` 可以抛异常。

### 5.2 数据结构（`algorithm/lpr/types.py`）

```python
from dataclasses import dataclass
from enum import Enum
from typing import Literal
import numpy as np

PlateColor = Literal["blue", "yellow", "green", "white", "black", "unknown"]
Point = tuple[float, float]               # (x, y)，原图像素坐标
Box = tuple[int, int, int, int]           # (x, y, w, h)

class RecogStatus(str, Enum):
    OK = "OK"
    LOW_CONFIDENCE = "LOW_CONFIDENCE"
    NO_PLATE = "NO_PLATE"
    SEG_FAILED = "SEG_FAILED"
    INVALID_FORMAT = "INVALID_FORMAT"
    UNSUPPORTED = "UNSUPPORTED"           # 特种车牌，暂不支持
    BAD_INPUT = "BAD_INPUT"
    INTERNAL_ERROR = "INTERNAL_ERROR"

@dataclass
```

### 5.4 置信度定义与 E1 阈值

- 逐位置信度 `char_confidences[i]`：该位在位置约束集合内选中字符的 softmax 原始概率（不在集合内重新归一化，避免虚高）。
- 整牌置信度 `confidence = min(char_confidences)`：短板原则，任何一位不可靠，整牌就不可靠。
- 多帧投票时的置信度见 6.7。
- E1 阈值 `postprocess.min_confidence` 初值 0.80，10-31 前在验证集上按“自动通过精度 ≥99%”反推最终值【待调】。
- 阈值只在 M2 配置中定义一份，M3 只看 `status` 判断，不另设阈值（已确认 Q4）。

### 5.6 线程安全与运行约定

- PlateRecognizer 实例在调用之间没有可变共享状态；模型处于 eval 模式，推理包在 `torch.inference_mode()` 中，可被多线程并发调用（支撑 G5 五车并发）。
- 启动时 `torch.set_num_threads(runtime.torch_threads)`，默认 2，避免与 Uvicorn 线程池争抢 CPU。
- 后端必须通过 `asyncio.to_thread` 或 `run_in_threadpool` 调用，不得在事件循环里直接调用。
- DuplicateFilter、PlateVoteSession 有状态，内部加锁；每个车道各建一个实例。
- 日志统一用 loguru：每次识别输出 1 行 INFO（车道、车牌、置信度、状态、耗时），各阶段耗时为 DEBUG。

### 6.2 阶段二 定位（员工 B）

```text
locate(pre):
    masks = [hsv_mask(pre.hsv, blue), hsv_mask(pre.hsv, yellow), hsv_mask(pre.hsv, green)]  # 颜色分支
    edge  = otsu(abs(sobel_x(pre.gray)))                                                     # 边缘分支，夜间与偏色兜底
    cands = []
    for m in masks + [edge]:
        m = morph_close(m, kernel = close_kernel_rel × work_width); m = morph_open(m, 3×3)
        for cnt in findContours(m):
            r = minAreaRect(cnt)
            if aspect(r) ∉ [2.0, 5.5] or area_ratio(r) ∉ [0.001, 0.08] or |angle(r)| > 30°: continue
            s = 0.35 × aspect_score(r) + 0.35 × color_ratio(r) + 0.30 × row_transition_score(r)
            cands.append(Candidate(r, s, source))
    cands = nms(cands, iou = 0.3)
    return map_to_original(top_k(cands, max_candidates), pre.scale, pre.offset)
```

- `aspect_score`：与 3.14（7 位）或 3.43（8 位）中较近者的相对偏差，映射到 0—1。
- `row_transition_score`：候选缩放到 136×36，取中间 50% 的行统计黑白跳变次数，平均 ≥12 记满分（字符区域的典型特征）。
- 颜色判别：候选区域内 HSV 像素多数投票 → blue / yellow / green / unknown。
- 可选增强（任务 B6）：HOG+SVM 车牌/非车牌二分类器复核候选，负样本取 ccpd_np 和随机背景块；只在定位精度不足时启用。
- 失败情形：车身与车牌同色（蓝色车）、强反光、夜间颜色失真、车牌过小。对策：边缘分支兜底、车道 ROI、候选回退。
- 评价指标：Top-3 定位召回（前 3 个候选中至少一个与真值框 IoU ≥0.5）。

### 6.3 阶段三 校正（员工 B）

```text
rectify(image, cand):
    crop = image[expand(cand.bbox, 10%)]                  # 在原图上取，保证分辨率
    quad = refine_quad(crop)       # 颜色/边缘掩膜 → 最大轮廓 → approxPolyDP 取 4 点；失败则用 minAreaRect 四点
    quad = order_points(quad)      # LT, RT, RB, LB
    layout = 8 if cand.color == green else (7 if cand.color in {blue, yellow} else 0)
    W, H = size_8 if layout == 8 else size_7
    M = getPerspectiveTransform(quad, [[0,0], [W,0], [W,H], [0,H]])
    plate = warpPerspective(image, M, (W, H))
    plate = deskew_residual(plate, ±10°, step 1°)         # 以水平投影方差最大为准则，可选
    return RectifiedPlate(plate, layout, cand.color, M, cand)
```

- 垂直错切（CCPD tilt 类常见）可在任务 B4 加入错切搜索：在 [-0.3, 0.3] 内找使竖直投影谷最深的错切系数【可选】。
- 失败情形：四点拟合偏差导致字符被截断 → 由分割阶段报 SEG_FAILED 并触发候选回退；结果中记录拟合方式，便于归因。

### 6.4 阶段四 分割（员工 B）

```text
segment(rect, layout):
    g = gray(rect.image)
    if rect.color in {yellow, green, white}: g = 255 - g     # 统一为“字符亮、底暗”
    b = binarize(g, otsu)                                     # 或 adaptive(block=15, C=-5)
    b = trim_rows(b)                                          # 按行跳变次数去掉上下边框与铆钉
    b = remove_small_cc(b, min_area = 0.002 × W × H); remove_border_touching_cc(b)
    slots = layout_slots(layout)                              # 版式先验：各位字符中心与宽度（相对板宽）
    off, scale = argmax 槽内墨迹总量(slots, 竖直投影(b))       # 版式模板与投影对齐
    boxes = [tighten(slot_box(i, off, scale), b) for i in slots]   # 槽内收紧到墨迹外接框
    if 存在空槽 or 字宽异常: return SegmentResult(ok=False)
    chars = [normalize_char(g[box]) for box in boxes]
    return SegmentResult(ok=True, layout, boxes, stack(chars), quality)
```

- 7 位版式先验初值（相对板宽）：字符中心 `[0.086, 0.216, 0.395, 0.525, 0.655, 0.784, 0.914]`，字宽 0.102；第 2、3 位之间有分隔点。数值依据常见的 GA 36 版式资料推算【待核实】，员工 B 须用 CCPD 真值校正图做统计校准。
- 8 位新能源版式由员工 B 在 CCPD2020 上统计后写入配置【待填：员工 B，截止 10-29】。
- 省份汉字常断成多个连通域（如“川”“沪”），按版式槽对齐会自然把它们合并，这是选用槽对齐、不用纯连通域分割的原因。
- 失败情形：字符粘连、污损遮挡、边框残留 → SEG_FAILED，并触发候选回退。

### 6.5 阶段五 字符识别（员工 A）

### 6.6 阶段六 后处理（员工 C）

```text
decode(probs, layout, color):
    hyps = {7: [L7], 8: [L8S, L8L]}[layout]                 # 版式假设，见附录 A
    for h in hyps:
        for i, allowed in enumerate(h.slots):
            c_i = argmax_{c ∈ allowed} probs[i, c];  p_i = probs[i, c_i]
        score_h = Σ log p_i
    h* = argmax_h score_h
    plate = join(c_i);  char_conf = [p_i];  confidence = min(p_i)
    candidates = beam_topk(probs, h*, k = 3)                # 备选车牌
    if not regex_match(plate):            status = INVALID_FORMAT
    elif confidence >= min_confidence:    status = OK
    else:                                 status = LOW_CONFIDENCE
```

- 位置约束集合：PROV（31 个省份字）、LETTER（24 个字母，无 I、O）、ALNUM（字母 + 数字）、DIGIT（数字）、DF（D 或 F）。
- 可选的省份先验 `postprocess.province_prior`（对本地省份乘系数）默认关闭；只有在本地样本上验证有效后才启用，并在报告中写明【待调】。
- 特种车牌（已确认 Q12）：白牌、黑牌按 4.4 返回 UNSUPPORTED；教练车“学”、挂车“挂”等黄牌末位是汉字，不在字符集内，通常落入 LOW_CONFIDENCE 或 INVALID_FORMAT，同样转人工。
- 车型提示：按 5.8 的表，由 `plate_color` 和选中的版式假设 h* 得出 `vehicle_type_hint`。

### 6.7 多帧投票（员工 C）

```text
vote(results):
    R = [r for r in results if r.status in {OK, LOW_CONFIDENCE}]
    if len(R) < min_frames: return 置信度最高的单帧结果
    L = 众数(r.layout for r in R);  R = [r for r in R if r.layout == L]
    for i in range(L):
        score_i(c) = Σ_{r ∈ R, r.plate[i] == c} r.char_conf[i]
        plate[i] = argmax_c score_i(c);  conf_i = score_i(plate[i]) / len(R)
    confidence = min(conf_i);  frames_used = len(R)
    plate_image = 置信度最高那一帧的校正图
    status 按 6.6 规则重新判定
```

流式 `PlateVoteSession(agree_frames=3, window_s=2.0)`：逐帧 feed；同一车牌 Top-1 累计达到 3 帧，或距首帧超过 2 s，就输出一次投票结果并重置。

### 6.8 重复抓拍判定（E7，员工 C）

```text
DuplicateFilter(window_s=30, dhash_max_hamming=10).check(lane_id, result, ts) -> (is_dup, reason)
    同车道、同车牌、时间差 ≤ window_s                                → 重复（same_plate）
    同车道、车牌编辑距离 ≤ 1、时间差 ≤ window_s、校正图 dHash 汉明距离 ≤ 10
                                                                     → 重复（similar_plate，疑似同车误识）
    其余情况：记录本次并返回不重复
```

M2 只给出判定；是否丢弃、停车会话如何幂等由 M3 决定，数据库层仍需保留“重复入场”校验。

## 8 模型训练与对比实验

### 8.1 CharCNN 结构（员工 A）

```text
输入 1×32×32（像素 / 255）
[Conv3×3-32,  BN, ReLU] ×2 → MaxPool → 16×16
[Conv3×3-64,  BN, ReLU] ×2 → MaxPool → 8×8
[Conv3×3-128, BN, ReLU]    → MaxPool → 4×4
Flatten(2048) → Dropout 0.3 → FC 256 → ReLU → Dropout 0.3 → FC 65
参数量约 68 万，float32 权重约 2.7 MB
```

### 8.2 训练配置

| 项 | 值 |
| --- | --- |
| 优化器 | AdamW，lr 1e-3，weight_decay 1e-4，余弦退火 |
| 轮数 / 批大小 | 15 / 256【待调】 |
| 损失 | 交叉熵，label smoothing 0.05；省份类加权或用 WeightedRandomSampler |
| 增广（OpenCV 实现，不用 torchvision） | 旋转 ±8°、缩放 0.9—1.1、平移 ±2 px、错切 ±0.1、高斯模糊 σ≤1.2、噪声、亮度对比度抖动、1 px 腐蚀/膨胀、小块遮挡（模拟污损） |
| 随机种子 | 42（random、numpy、torch 一致） |
| 设备 | CPU；DataLoader `num_workers` 取 0—2 |
| 保存 | 只存 state_dict；加载用 `torch.load(..., weights_only=True)` |
| 验收 | 验证集字符准确率 ≥98%，省份字 ≥95%【待调】；8 个字符批量推理 ≤10 ms |

### 8.3 基线方法

| 方法 | 做法 | 概率输出 |
| --- | --- | --- |
| 模板匹配 | 每类取训练样本均值图（或 K=5 个代表样本）作模板；`cv2.matchTemplate(TM_CCOEFF_NORMED)` | 得分经温度 softmax 转概率 |
| HOG+SVM | `cv2.HOGDescriptor((32,32),(16,16),(8,8),(8,8),9)` 得 324 维特征；sklearn `SVC(kernel="rbf", C=10)`，每类最多 500 个样本（总计约 3 万；RBF 核训练时间随样本数近似平方增长） | `probability=True` 或 `CalibratedClassifierCV` |

### 8.4 对比与消融实验（写入评测报告）

| 实验 | 变量 | 指标 |
| --- | --- | --- |
| 三方法对比 | 模板匹配 / HOG+SVM / CNN（同一字符测试集、同一流水线） | 字符准确率（总体、省份字、字母数字）、整牌准确率、单字符耗时、模型大小、训练耗时 |
| 阶段消融 | 去掉 CLAHE / 去掉透视校正 / 去掉位置约束解码 / 去掉候选回退 | 整牌准确率变化 |
| 多帧投票 | 单帧 / 3 帧 / 5 帧 | 视频片段整牌准确率 |
| 真值定位 | 用真值四角点替代阶段二、三 | 识别准确率上限，衡量定位造成的损失 |

## 15 常见坑

| 坑 | 正确做法 |
| --- | --- |
| `cv2.imread` 遇到中文路径返回 None | `cv2.imdecode(np.fromfile(path, np.uint8), cv2.IMREAD_COLOR)`，统一走 `io_utils` |
| `cv2.imwrite` 写中文路径失败 | `cv2.imencode(".jpg", img)[1].tofile(path)` |
| 颜色通道搞混 | OpenCV 默认 BGR；HSV 的 H 取值 0—179，不是 0—360 |
| `cv2.putText` 不能写中文 | 调试图上标注用字符下标或拼音 |
| 同时装了 opencv-python 和 opencv-python-headless | 两者冲突，只装一个 |
| Windows 下 DataLoader 多进程报错 | 训练脚本必须有 `if __name__ == "__main__":`；`num_workers` 取 0—2 |
| 加载权重有安全隐患 | 只存 state_dict，用 `torch.load(..., weights_only=True)` |
| torch 线程过多拖慢后端 | `torch.set_num_threads(2)` |
| 结果不可复现 | random、numpy、torch 统一种子 42 |
| CCPD 原图是竖幅 720×1160 | 测 G1 时按规则补边缩放到 1280×720 |
| CCPD 省份字绝大多数是“皖” | 见 7.3 均衡策略与 K2 |
| CCPD 下标中的 `O` 是“无字符”占位符，不是字母 O | 解析时跳过含占位符的样本 |
| CCPD 四角点从右下角开始（RB, LB, LT, RT） | 解析时转换为本文约定的 LT, RT, RB, LB |
| scikit-image 不在白名单 | HOG 用 `cv2.HOGDescriptor` |
| `SVC(probability=True)` 训练很慢（内部还要做 5 折交叉验证） | 每类样本上限 500；仍然太慢就改用 `LinearSVC` + `CalibratedClassifierCV` |
| 坐标与 numpy 索引混淆 | 对外坐标 `(x, y)`；numpy 索引是 `[y, x]` |
| 模型与字符表版本错配 | manifest 记录 charset_sha，加载时校验 |
