## 1 项目背景（来自课程任务书）

任务原文要点：采用软件工程专业知识与图形图像、视频处理技术，**设计并实现一个车牌识别停车场收费系统**，包括车牌识别、车辆进出场控制逻辑、3D 动画和数据库计收费模块，并完成数据与测试模拟。

**任务书列出的 8 条功能要求（必须 1:1 覆盖，不得删减）**

| 编号 | 任务书原文要求 | 本项目承接方式 |
| --- | --- | --- |
| R1 | 能够通过进场和出场车辆图像识别车牌号 | 自研识别流水线（定位→校正→分割→CNN 识别→后处理） |
| R2 | 能够对进出过程控制、对停放时间计算并按收费标准计算停车费 | 出入场状态机 + 计费引擎 |
| R3 | 能够将出场停车费用、车牌号以及车辆照片显示出来 | 岗亭值班界面（一屏三要素） |
| R4 | 已交费车辆可手动或自动抬杆放行（抬杆用 3D 动画模拟） | Three.js 场区与道闸动画，受后端事件驱动 |
| R5 | 管理员能够对收费标准进行设置 | 费率配置（版本化、即时生效） |
| R6 | 按天/周/月/季/年统计停车数量与所收费用 | 多粒度统计查询 |
| R7 | 其他统计报表生成及打印（可生成 PDF 存储） | 日结/月结报表导出 A4 PDF |
| R8 | 其他附加功能（加分项）+ 正常/异常工作流程设计 | 至少 2 项加分功能 + 8 类异常流程 |

**系统难点（任务书明确）**：车牌识别算法、出入场控制算法逻辑、动画呈现、数据库报表系统。
**算法要求**：可参考模板匹配、支持向量机、神经网络与深度学习；**不鼓励直接调用现成车牌识别 API**。
**平台要求**：语言与平台不限（VC++、Java、Python、OpenCV、OpenGL、Matlab、Blender、Unity3D 等均可用），本项目已统一选定（见第 3 章），AI 不得擅自更换。

| 实时 | WebSocket（FastAPI 原生） | — | 识别与道闸事件推送 |
| 测试 | pytest、pytest-cov、Apifox | — | 单元 / 接口 / 场景 / 基准 |
| 部署 | Docker Compose + Nginx（可选） | — | 一键起服务 |

**选型理由（文档中必须写入，答辩会被问）**
1. Python 单栈：算法、后端同语言，避免跨语言序列化与联调成本。
2. FastAPI 自动 OpenAPI：前后端可并行开发，异步 IO 适配视频流与 WebSocket。
3. 自研识别不调 API：符合任务书“不鼓励调用现成 API”，OpenCV/PyTorch 仅作通用框架。
4. MySQL 8.0：日/周/月/季/年聚合依赖窗口函数与日期函数。
5. Three.js：与 Web 前端同栈、免安装运行时，演示与录屏成本最低。
6. 费率版本化：避免历史账单被新费率追溯改写。

## 8 接口契约（**冻结，AI 不得更改路径**）

- 统一响应体：`{"code":0,"message":"ok","data":{...},"traceId":"..."}`
- 分页：`?page=1&size=20` → `{"total":n,"items":[...]}`
- 时间：ISO-8601，时区 `Asia/Shanghai`
- 错误码分段：`1xxx` 鉴权｜`2xxx` 业务（无会话、未缴费、重复入场）｜`3xxx` 算法（识别失败、置信度低）｜`4xxx` 数据（不存在、冲突）｜`5xxx` 系统

| 方法 | 路径 | 说明 | 归属 |
| --- | --- | --- | --- |
| POST | `/api/v1/auth/login` | 登录，返回 JWT | M6 |
| POST | `/api/v1/entry/capture` | 入场抓拍识别并建档 | M3 |
| POST | `/api/v1/exit/capture` | 出场识别、匹配会话、计费 | M3 |
| POST | `/api/v1/payment/{session_id}` | 缴费（现金/模拟扫码） | M4 |
| POST | `/api/v1/gate/{lane_id}/open` | 抬杆（自动/手动，手动需授权与原因） | M3 |
| POST | `/api/v1/gate/{lane_id}/close` | 落杆 | M3 |
| POST | `/api/v1/plate/correct` | 人工改牌并重算 | M6 |
| GET/POST/PUT | `/api/v1/fee-rules` | 费率查询/新增/修改 | M6 |
| GET | `/api/v1/records` | 通行记录分页检索 | M6 |
| GET | `/api/v1/stats?granularity=day\|week\|month\|quarter\|year` | 多粒度统计 | M6 |
| GET | `/api/v1/reports/export?type=daily\|monthly` | 生成并下载 PDF | M6 |
| WS | `/ws/lane/{lane_id}` | 识别结果、缴费、道闸状态推送 | M3 |
| GET | `/api/v1/health` | 服务与设备健康检查 | M6 |

**关键算法（写入设计文档时必须给伪代码）**

```
计费：duration = exit_time - entry_time
      usable   = max(0, duration - free_min)
      units    = ceil(usable / step_min)
      fee      = min(units * step_price(vehicle_type, 时段), daily_cap*天数)
      月卡有效 → fee = 0（记录车牌与有效期）

状态机：IDLE→DETECTED→CAPTURED→RECOGNIZED→VALIDATED→OPENING→PASSING→CLOSING→IDLE
        任一环节异常 → EXCEPTION（人工介入）→ 记日志 → 回 IDLE
        约束：PASSING 禁止落杆；OPENING 超时 5s 告警
```

**P6 测试计划**：1 范围与策略｜2 环境与数据｜3 用例（表头：编号/前置/步骤/期望/优先级，至少给出 FR-01—FR-15 + E1—E8 的空行）｜4 性能与稳定性｜5 缺陷管理｜6 报告模板

### 11.4 写作规范

1. 中文技术文体，不用第一人称，不用“我们觉得”这类表述。
2. 每个量化指标必须写“目标值 + 测量方法”。

4. 表格优先于长段落；每个功能需求、每条异常、每个接口都要有编号。
5. 待补内容统一写 `【待填：负责人，截止 MM-DD】`，不要留空或写 TBD。
6. 不编造第三方 API、不写“使用某云车牌识别服务”、不引入第 3 章以外的库。
