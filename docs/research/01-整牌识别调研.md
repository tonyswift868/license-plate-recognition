# 整牌识别调研与 WP-A 方案

调研截止：2026-10-26。本文只总结论文、官方数据集说明和公开仓库自报结果；不复制源码、不使用或下载第三方权重。不同数据版本、指标、推理边界和硬件分别说明，不能把表格数字当成同一协议下的横向竞赛。

## 结论与本轮方案

本轮续训自有 CRNN v1，使用 v2 难例整牌数据和本地增强，不重做架构。v1 为 218,474 参数、权重 0.887 MB；既有 2 线程单块 read 历史约 3.8 ms。该读时是本项目既有读牌器测量，不代表整帧 P95。模型尺寸与CPU时间以本地模型和当前运行时重新核验为准。

采用以下计划采样配比；若最终训练脚本调整，回执按实际配置修订：

- 样本池：难例 70%，其中 DB、Blur、Tilt、Rotate、FN、Challenge、Weather 七组等权（各占总采样的 10%）。
- 常规与补充样本：Base-7 为 12%，真实新能源 8 字牌为 10%，字体合成 7/8 字牌为 8%。
- 难例来源：真值四角点裁片 65%、真实流水线候选四角点校正裁片 35%。训练和留出划分以原图为单位，确保同一原图的所有裁片不会跨入训练和调参两侧。
- 温度缩放只在调参集 fit 半边拟合，并在未参与温度拟合的 report 半边报告校准前后置信度分档；两半均用于训练轮次选择，因此 report 不作为独立盲测；不以 val1000_v1 或 devhard_v1 拟合温度或选择超参数。agree 模式沿用默认置信度参数，只由仲裁模式不同；不在本轮定阈值。

与整牌 CTC、透视校正、灰度预处理、合成省份/新能源牌等已有能力衔接。重点补低亮度、模糊、透视与倾斜的覆盖；不修改流水线或运行时默认配置，不用预训练权重，也不借用他人实现。暂不引入大型检测器或 learned rectifier，也不做 OpenVINO 扩展：前两者超出当前单牌读牌模块边界，后者需要额外运行时/部署验证且 LPRNet 论文已显示 CPU 表现强烈依赖后端。

数据隔离工具已生成七类各 300 原图（3,957 裁片）的调参集，并从 v2 val 剔除受保护最终清单对应的 2,383 裁片，剩 7,617 裁片。具体 SHA 与原图隔离证据见本轮 audit.json。旧开发指标中已看过本项目 CRNN v1/CNN v2 的历史表现；本轮 val1000_v1、devhard_v1 不是对本项目的首次盲测，本轮结果只作最终报告，不据此再调参。最终固定清单不用于训练、温度拟合或模型选择。

## 对照来源与边界

### LPRNet：轻量整牌 CTC 参考

来源：Zherzdev 与 Gruzdev，[arXiv 1806.10447](https://arxiv.org/abs/1806.10447)，[PDF](https://arxiv.org/pdf/1806.10447)。

- 结构与输入：PDF 第 1–2 页、表 1–3。RGB 94×24 输入，可选 LocNet 空间变换，轻量 CNN、逐位置字符分类头和 CTC 解码；无 LSTM。CNN 基本块借鉴 Fire/Inception 思路，配合 BN、ReLU、Dropout 与全局上下文。论文可选贪心或 beam/prefix 解码。
- 计算和模型大小：表 4（PDF 第 3 页）给 baseline/basic/reduced 的计算量分别为 0.71/0.34/0.163 GFLOPs，准确率 94.1/95.0/94.0%。该表没有给参数数或模型文件字节数。LPTR-AFLNet 论文第 1 页称其引用的 LPRNet baseline 约 467K 参数；这不是原 LPRNet 表 4 各变体的同一模型/导出尺寸，不能据此宣称本地模型小于某字节门槛。
- CPU/GPU：表 6（PDF 第 4 页）给 GPU+cuDNN 3 ms、Intel Core i7-6700K 上 Caffe CPU 11–15 ms、同机 Intel OpenVINO IE CPU 1.3 ms；GPU 为 NVIDIA GeForce GTX 1080。1.3 ms 是 OpenVINO 后端结果，不能泛化到任意 CPU 实现；Caffe 结果反而超过 10 ms。不能把 GPU 数字当 CPU。
- 数据/准确率：第 4.1 节（PDF 第 3 页）是在私有中国车牌裁片集的 11,696 张人工标注图上按 9:1 划分训练/验证。表 4 的 94–95% 不是 CCPD 结果；附近没有说明这是官方 CCPD 协议下的整牌完全匹配率。
- 训练启发：第 4 节（PDF 第 3 页）用 Adam、batch 32、初始 LR 0.001、250k iterations；做随机仿射旋转、缩放、平移。训练裁片有边缘背景变化，也有过紧裁切甚至部分车牌被裁掉的情况。论文称不做数据增强和全局上下文就无法从零训练其模型；LocNet 在前 5k iterations 后才加入。特定低光照变换配方未报告。
- 适用性：证明分割自由 CNN+CTC 和轻量识别可行；CPU<10 ms 取决于运行后端，尺寸须对实际导出物测量。论文的训练数据、拆分和字符集与本项目不同，不能直接转移其准确率。

### CCPD 官方仓库与 ECCV 2018 RPnet：注意年份与协议

来源：[detectRecog/CCPD 官方仓库](https://github.com/detectRecog/CCPD)，[ECCV/ECVA 2018 原论文 PDF](https://www.ecva.net/papers/eccv_2018/papers_ECCV/papers/Zhenbo_Xu_Towards_End-to-End_License_ECCV_2018_paper.pdf)。

**原论文 RPnet。** PDF 第 7–9 页，图 3、§4：RGB 480×480 全图输入，十层卷积共享检测/识别特征；FC 分支回归车牌框，识别分支从三个浅层特征做 ROI pooling（各 8×16，合并为 8×16×416）并由七个字符分类器输出车牌。它是整合检测与识别的全图网络，不是轻量裁片识别器。论文没有提供 RPnet 参数量或模型文件大小，≤5 MB 无证据。

- CCPD 版本：原论文 PDF 第 5–6 页图 2、表 3 约 250k 张图：Base 200k、DB 20k、FN 20k，Rotate/Tilt/Weather/Challenge 各 10k，Blur 与 NP 各 5k。§5.1（PDF 第 10 页）将 Base 对半，100k 训练、100k Base 测试；其余子集用于评测。表 5（PDF 第 11 页）没有 Blur 列。
- 原论文 Table 5 recognition precision（百分比）：总体 AP 95.5、Base(100k) 98.5、DB 96.9、FN 94.3、Rotate 90.8、Tilt 92.5、Weather 87.9、Challenge 85.1；Blur 未报告。识别正确条件是检测框 IoU>0.6 且所有字符均正确（§5.3，PDF 第 10–11 页），所以是定位+整牌完全匹配联合成绩，不是给定真值裁片的纯识别率。
- 速度与硬件：论文 §5.1（PDF 第 10 页）称评测桌机为 8 核 3.40 GHz Intel Core i7-6700、24 GB RAM + Quadro P4000 GPU；除 Cascade 外的评测模型依赖 GPU。Table 5 的 61 FPS 是 GPU 参与的整合推理吞吐，论文没有 CPU-only RPnet 数值。
- 训练：§4.2（PDF 第 9 页）说明检测模块在 CCPD 上从零预训练 300 epochs，再进行端到端训练；不依赖 ImageNet 预训练。官方仓库的当前 README 则给出先训练/加载 wR2 localization，再设置 wR2Path 训练 RPnet 的流程，并提供 checkpoint 链接；这是另一份仓库训练说明，不能与论文从零检测模块的实验描述混为同一 checkpoint 状态。

**2019 更新后的官方 README 基线。** 仓库 README 标注 2019-10-03 数据更新，超过 300k 张且标注有细化；Base 用于 train/val，DB、Blur、FN、Rotate、Tilt、Challenge 用于 test。README recognition 表的 SSD512+HC 数值为 FPS 11、整体 43.42、DB 34.47、Blur 25.83、FN 45.24、Rotate 52.82、Tilt 52.04、Challenge 44.62。该行是 SSD512+Holistic-CNN 的检测+识别基线，**不是 RPnet**。README 说识别需全部字符正确，但短指标说明没有原论文额外 IoU>0.6 的联合条件。该表速度硬件未标明，不能称为 CPU 速度。原论文 RPnet 表和新 README SSD+HC 表不可拼接或互换。

### LPTR-AFLNet：透视校正/识别一体化参考

来源：[arXiv 2507.16362](https://arxiv.org/abs/2507.16362)，[PDF](https://arxiv.org/pdf/2507.16362)。

- 结构：LPRNet 类整牌 CNN+CTC、LP-CA 注意力与 Focal CTC，并增加透视变换校正 PTR。PDF 第 9 页图 8 示意 94×24 裁片；全文未把它定义成所有部署情境下的完整输入契约。模型大小与参数量不要互换。
- CCPD 表 2（PDF 第 20 页）列为 AP、Base、Db、Fn、Rotate、Tilt、Weather、Challenge、Double、FPS、Size(M)。LPRNet 行：98.35、99.49、98.29、98.62、98.73、98.77、97.04、87.08、unsupported、129、1.8；LPTR-AFLNet 行：98.87、99.69、98.99、99.11、99.15、99.19、97.89、90.39、99.37、107、2.7。表头没有 Blur 列；不能将 Db 擅自改成 Blur。表头的 Size(M) 没有定义单位，故 1.8 和 2.7 只能按原表记录，不能写成 MB 或参数量。
- 协议边界：§4.3.2（PDF 第 19 页）称表格上部结果来自开源实现复现；对于缺少公开代码的集成模型，作者用随机扰动顶点模拟定位误差，再进行识别。LPTR 数值涉及透视校正+识别，不是完整全图检测结果。论文 CCPD 表准确率的精确分母/匹配规则未在 Table 2 表头充分展开，不与官方 CCPD 表直接等同。
- CPU/GPU：表 4（PDF 第 21 页）列 Xeon E5-2620 CPU-only 79 FPS、i7-7700K 50 FPS、i7-4770K 33 FPS；这是论文集成模型测试报告的吞吐，批量、线程、预热和具体计时边界未充分说明。倒数约为 12.7/20/30.3 ms/帧，仅能视为吞吐的倒数，不等价于本项目单块 read() 延迟。其 GPU <10ms 说法不能作 CPU 结果。
- 训练与增强：表 1、图 24（PDF 第 17 页）给 batch 300、Adam、LR 0.001/0.0005、momentum 0.9、200 epochs，三阶段训练：精确定位裁片预训练识别器，冻结识别器训练 rectifier，最后联合微调。图 15（PDF 第 14 页）展示合成双层牌的光照场景和 Gaussian/motion/pixel blur；第 12–15 页包括顶点扰动模拟定位误差。光照合成不是一个明确可复用的低光照参数配方。
- 适用性：可借鉴透视扰动和模糊/光照覆盖；模型含 learned rectifier，当前范围不做。表中 Size 单位不明、CPU速度协议不充分，不证明目标的字节和单次延迟门槛。

### CRPD：全图多车牌系统，非本项目识别器替代项

来源：[arXiv 2205.03582](https://arxiv.org/abs/2205.03582)，[PDF](https://arxiv.org/pdf/2205.03582)，[作者仓库](https://github.com/yxgong0/CRPD)。

- 结构/输入：PDF 第 8–13 页，全图 STELA-style anchor/FPN 检测、旋转框回归与 anchor refinement，RRoIAlign 后接 CRNN 风格卷积+BiLSTM+CTC 识别器，含 deformable conv/residual block。全图 640×640×3，识别特征 crop 8×25。参数量和文件大小未报告。
- 性能与协议：Table 9（PDF 第 17 页）在作者 CRPD 数据上的 Ours：CRPD-all 95.4 recall / 84.1 precision / 89.4 F-score / 30 FPS，single 96.3/83.6/89.5/35 FPS；是检测与识别整体指标，不是整牌纯识别准确率。该表未列推理硬件；论文训练机器是 Xeon E5-2630 v3 + TITAN RTX（§5.1，PDF 第 13 页），不能把训练机器当推理速度。CCPD Table 10（PDF 第 18 页）是 aggregate precision；没有找到 DB/Tilt/Blur 分项。
- 论文匹配定义是全文 exact match 且 IoU>0.6（PDF 第 14 页），与官方 CCPD 的简短说明也不能默认相同。没有 CPU 延迟或模型大小；目标 CPU/5 MB 不适用。它可作为未来需支持全图、多牌检测的参考，而非当前单牌裁片模型基线。

| LPTR-AFLNet | Size(M)=2.7，单位不明 | CPU系统吞吐表倒数约12.7–30.3ms/帧，协议不充分 | 三阶段训练，但涉及 learned rectifier | Table2 DB/Tilt有值、无Blur；随机顶点扰动/整合系统协议 |

适用路线是继续做小型单牌识别器，保留现有透视校正/分割共存流水线，先通过均衡难例训练提升识别，再用 fit/report 分开的温度校准和 agree 仲裁流水线评估自动通过精度。完整检测器、多个识别器级联或 learned rectifier 当前不值得增加：模型字节、CPU延迟和训练成本均没有满足本项目限制的证据。通过固定样本对比报告结果，不在结果集上再调参数。

## 统一口径提醒

- CCPD DB 的论文定义是车牌区域暗、不均匀或极亮，不等同于只有夜间；Blur 是手抖造成的模糊。按 CCPD 原标签分别报告，不把 DB 改名“夜间”，夜间字段筛选另行说明来源。
- 官方 CCPD recognition 正确要求全牌字符正确；ECCV 2018 RPnet Table 5 还要求检测 IoU>0.6。检测 AP/IoU>0.7、识别整牌准确率、字符准确率、定位+识别precision、FPS不能混写。
- 表格中的FPS只在硬件及模型边界明确时附带说明；GPU不是CPU。LPTR Table 2 的 Size(M) 单位未定义。仓库作者自报的“MB/M”除明确写出外仍不视作与本地state_dict字节数等价。
- 本轮不下载、引用或复制第三方源码和权重。引用只用于架构/实验思路；本项目训练代码和模型权重保持自有。
