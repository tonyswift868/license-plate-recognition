# 候选框与多裁片选择调研

调研日期：2026-10-27。重点核对生产 ALPR/OCR 接口和一手论文，区分定位候选框、裁片/增强视图、文本候选以及跨帧合并。公开资料没有给出可直接照搬到本项目、并保证收益的通用排序公式；以下做法是可试验的设计选项，不把论文结果当成本地指标。

## 当前 pipeline 的实际语义

`PlateRecognizer._run` 先按定位分数取候选；启用角点网络时，将网络候选放在传统候选之前，按 IoU 去重并补位。每个候选再按 `rectify_candidates` 的顺序生成校正裁片，逐个尝试布局。`agree` 模式在同一校正图上取一个分割路线结果和一个 CRNN 结果仲裁；任一候选/裁片第一次得到 `OK` 就立即返回，后续候选和裁片不会参与比较。没有任何 `OK` 时，才用 `_rank(status, confidence)` 保存较优回退结果；这时优先级是状态等级，其次置信度。`first_ok` 则在分割路线第一次得到 `OK` 时提前返回，只有分割没有 `OK` 才运行该候选的 CRNN 兜底。若最终没有 `OK` 且首候选颜色为白/黑牌，还会返回 `UNSUPPORTED`。

所以当前并不是“把所有候选跑完，按联合分数挑最高者”：网络候选优先次序、每个候选的 rect 次序以及首次 `OK` 都会影响最终读法。检测分数和识别分数当前没有联合排序。GT 四角点、GT 颜色/版式和 bbox IoU 只能用于诊断上限、分桶或离线配对比较；它们在推理时不可用，不能作为线上挑候选的规则，也不能用真值事后选择最佳裁片。

## 公开系统和论文中的做法

### 多候选与识别确认

OpenALPR 的官方开源接口示例会为车牌输出 Top-N 文本假设及各自 confidence，可通过 `topn` 改候选数；示例也显示候选是否匹配地区模板。其视频流接口会把同一车辆相邻帧的结果合并，并保留最高置信结果。[OpenALPR README](https://github.com/openalpr/openalpr/blob/master/README.md) [OpenALPR on-premises SDK](https://github.com/openalpr/doc/blob/master/source/on_premises_sdk.include)

另一项实时车牌识别研究描述了两阶段验证：先用统计规则在定位阶段低成本过滤候选，再在字符识别后用字符结果继续验证候选。这支持“识别证据可以回头帮助候选验证”的架构方向，但其具体算法和效果不能直接迁移成本地阈值。[Recognizing License Plates in Real-Time](https://arxiv.org/abs/1906.04376)

### 多裁片和测试时变换

一篇 2026 年雾天 ALPR 研究对每张车牌裁片生成 RAW、CLAHE 和超分辨率加 CLAHE 三种版本，分别 OCR，再综合 OCR confidence、车牌结构有效性和歧义惩罚选文本；在其 945 张雾天图像上，作者报告相对最强单视图准确率提升 3.70 个百分点，同时报告全流程平均 471.42 ms/图。该结果说明多变体需要一个显式的文本选择规则，也揭示了推理成本；其雾天数据和设备条件与本项目不同，数值不能外推。[Arafat et al., Adaptive Multi-Variant Enhancement and OCR Selection for Robust License Plate Recognition in Hazy Conditions](https://doi.org/10.19139/soic-2310-5070-3818)

针对一般图像分类的测试时增广研究指出，可对同一图像应用语义保持变换，用各视图预测的一致程度估计分类可靠性；变换必须符合任务语义，不能机械套用翻转等增强。该论文在图像分类任务上实验，不是车牌 OCR 的精度证据。对车牌而言，建议只考虑小幅、真实成像合理的边缘/亮度/校正变体；水平翻转会破坏车牌字符顺序，不应使用。[Bahat & Shakhnarovich, Classification Confidence Estimation with Test-Time Data-Augmentation](https://arxiv.org/abs/2006.16705)

官方 PaddleOCR 文档将文本、识别置信分数及文本区域一并返回，并提供文本方向分类/校正模块。这说明现成 OCR 的结果可支持“识别结果+分数+区域/方向”的后处理接口；文档没有声称该分数已校准为整牌正确概率，也没有规定多裁片间应取最大分。[PaddleOCR text recognition module](https://www.paddleocr.ai/v3.3.1/version3.x/module_usage/text_recognition.html)

### 检测与识别的联合使用

VSNet 论文采用定位/顶点估计后重采样校正，再用 SCR-Net 识别的级联结构，并按检测框 IoU 区间分析识别效果。它说明识别器应在实际预测定位输出上评估，而不只看 GT crop；也说明定位与识别可以通过级联共同设计。它不是“检测 confidence 与 OCR confidence 可以直接相加”的依据。[Zhang et al., Rethinking and Designing a High-performing Automatic License Plate Recognition Approach](https://arxiv.org/abs/2011.14936)

## 对本项目可直接采用的方案

1. **先离线记录完整候选链。** 对每张固定名单图，保留候选来源/顺序/检测分数、bbox、与真值框 IoU（仅诊断）、每个校正假设及颜色/版式、分割和 CRNN 的文本/置信度/格式状态、最终选中候选，以及识别调用数和耗时。按照现在的短路规则记录“本来不会执行到”的候选时，必须将额外诊断推理标成 shadow/offline，避免误写成真实 pipeline 调用。
2. **将定位召回和选择质量分开报。** 报 Top-1/Top-3 IoU 命中；在命中候选中再报首候选正确、Top-3 任一候选/裁片能读对、真实当前策略最终正确。后两者的差值可以界定候选次序/裁片筛选的可改善空间。IoU 或 GT crop oracle 只作离线诊断，不可用来推理时排序。
3. **评估显式排序与 first-OK 的差异。** 离线完整执行固定 Top-3 和有限校正假设，比较现行 first-OK、第一候选 CRNN、所有候选 CRNN 置信度最高、同文本跨路线/跨裁片支持、结构合法性优先等规则。除了整牌准确率，同时记录固定阈值下 OK 集合是否变化、val/devhard 自动通过精度、各子集表现、extra calls 和 P50/P95；上线选择若改变自动通过集合，应重新扫 E1 并用真实流水线复跑。
4. **先试结构化、可解释的 joint score。** 对每个实际候选/裁片记录定位器原始分数、识别分数、格式/字符位置约束是否通过、跨视图读法一致度、裁片质量特征；在独立的训练/开发数据上拟合或校准组合分数，再用单独固定验证集选阈值。不要直接把未经校准的 detection score 与 reader confidence 相加或相乘：两者可能尺度不同、错误相关，而且当前 confidence 是模型分数，不自动等同于预测正确率。若样本量不足以可靠拟合，优先使用明确的字典序规则或门槛规则，并报告消融。
5. **让额外裁片按需运行。** 可先跑第一候选的当前路线；只有低置信、路线分歧、格式失败或分割失败时，再扩展到下一个候选或第二个裁片。给每层设置调用上限，并对容易样本保持早停。若要比较置信度，建议以整牌正确为目标，在开发数据上比较 score calibration、准确率和 coverage/risk 曲线；跨裁片同文支持可以作为额外特征，不要当成独立样本多数票。
6. **对文本投票用字符串级方法。** 多裁片可能输出不同长度，不能不加对齐地逐字符平均概率。可先按完整字符串分组，再以经验证的整牌置信度和结构合法性排序；需要合并近似字符串时，用编辑距离/序列对齐做离线分析并保留每个视图来源。相邻视频帧的投票与同一张图的不同裁片不等价：裁片高度相关，不能按独立观测累计置信度。
7. **将真实 CPU 延迟作为共同约束。** 多候选、多视图会增加识别调用；先以难例触发的有限 TTA 做性能试验，再对目标机器跑正式 G1。文献中的准确率增益或 GPU 速度不能替代本地整牌口径和 G1 P95。

上述是基于公开接口/论文和当前实现做出的工程推论；尚未证实任何单一商业 ALPR 系统使用与本项目完全相同的联合排序方案。应由固定开发数据上的配对实验决定是否采用，不以 GT oracle 结果直接生成运行时策略。
